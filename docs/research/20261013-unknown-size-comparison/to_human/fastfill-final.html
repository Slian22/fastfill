FastFill 布局系统交付

输入房间信息（边界、层高、门窗、固定物、房型）和需要的家具清单，输出每件家具的 bbox 尺寸、位置、朝向和支撑关系，可直接导出到 RoomGenBench 生成 3D 场景。下面所有数字都来自实测；未测的格子标“待测”。

交付物：一个系统

flowchart LR
  A[房间 + 家具清单] --> B[尺寸：训练集先验]
  B --> C[27B 布局模型]
  C --> D[S1 确定性修复]
  D -->|通过检查器| F[输出 bbox + 布局]
  D -->|未通过| E[升级：gpt-6.1-sol，再不行用开源 O2]
  E --> F
  1. 尺寸：每类家具用训练集统计的尺寸（先验）。LLM 自己给尺寸会系统性偏小，见表 5。
  2. 布局模型：27B 学生模型（Qwen3.8-27B + LoRA，用 40,000 个房间做 SFT，推理时不开思考，vLLM 服务）。修订 021 §4 在 rpo-dpo1（旧 8B）、op-dpo2-e1、27B 三者中按预注册规则选出；在 3,000 个 dev 确认房上（vLLM）检查器通过率比 rpo-dpo1 高 +0.053 [+0.037, +0.068]，在 8,647 个测试房上高 +0.044 [+0.033, +0.056]。
  3. S1 修复：只沿 XY 平移支撑子树，不改类别、尺寸、朝向和支撑关系；不用 GPU、不用 API。
  4. 升级：只有修复后仍不通过检查器的房间才升级：队列评测用 gpt-6.1-sol 再 O2，全测试只用开源 O2（需要 2 张 GPU）。升级时尺寸锁死。修好的房间用新布局，修不好的返回最好的候选，不会返回空输出。

我们的做法和发现

  1. 尺寸和摆放分开。尺寸用数据统计，模型只学放在哪。输出的家具是正常大小，RoomGenBench 里不会出现缩小的家具；代价是摆放更难（真实布局换成先验尺寸后检查器也只有 0.433）。
  2. 微调一个不思考的 27B。同一底座不思考时几乎不会摆（0.08）；用我们的数据做 SFT 后不思考也有 0.556（队列）/ 0.443（全测试），在测试集上比旧 8B 高 +0.044 [+0.033, +0.056]。它没有追上 O2 长思考的单次水平（0.787），推理开销没有测量。
  3. 确定性修复 S1。不用 GPU 和 API，全测试检查器 0.443 → 0.742，不改任何尺寸、朝向和父子关系（不变量计数全为 0）。
  4. 分级升级。只把修复后仍失败的房间交出去，队列上 14.6% 的房间用了 API；检查器 0.993，required = {} 准入与 L 相当，严格准入仍低于代理。
  5. 偏好数据的来源很关键。OptiScene 式的合成扰动负例让模型变差；用模型自己的失败配上它的 S1 修复做偏好对，严格准入比同数据 SFT 高 +0.058 / +0.053（两个种子），检查器没有区别。这个模型没过关系保持护栏，所以没有交付。

做得不好的地方

  • 严格准入低。完整系统 0.520，比拿同样尺寸的 L、O2 低 0.18–0.21；全测试上 27B + S1 只有 0.291，和旧模型（0.288）、真实布局（0.295）差不多。
  • 大房间。21 件以上家具的测试房（1,433 间）27B 单次只有 0.018；S1 后 31–50 件 0.304、51 件以上 0.127，严格准入接近 0。
  • 重叠。全测试 27B 的 OOR 0.256，真实布局 0.079。
  • 视觉。交付系统还没渲染。旧 8B 模型的 FID 最好，但 GPT 评分最低（两位评委都是 GPT-6 家族），网格级无碰撞房间 0.548，低于真实布局的 0.797。
  • 评测范围。单种子、历史测试划分；升级设计用 pilot 房模拟过；没有人工评审（UR）。
