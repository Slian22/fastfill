## 1. 结论

1. **大房间失败不是主要因为“抄上一条”。** 抄写确实普遍：21–50 件房 80% 有精确重复，51+ 件 99%。但把所有重复物体删掉，S1 后失败的含重复房也只救回 29%（335/1,138），全 test 上限 +0.039。根源有两层，见第 2 节。
2. **先验尺寸让大房间的 GT 摆法本身就放不下。** 同一批房间、同样的 GT 位置和朝向，只把尺寸换成先验：21–50 件房 checker 0.770 → 0.124，51+ 件 0.790 → 0.061。失败主要是同一父物体上的小物件互撞和地面家具互撞。
3. **现成方法里最值得马上拿来的是确定性的“只重摆失败物体”求解器**（PolyLayout 式墙锚定搜索）。免费、CPU、不改尺寸和朝向：S1 后仍失败的 300 间 test 房 checker 0 → 0.64。O2 对同类房的修复率是 57%，而且每间要约 18 GPU 秒。
4. **strict 准入卡在门可达（A3）和同父物体包围盒重叠（A4）**，S1 从不把这两项当修复目标。LabBuilder 式可达修复在本地实测让全 test strict +0.016。
5. **训练侧没有便宜的大收益。** DPO 改进版被两位质疑者驳回。自蒸馏和 GRPO 经质疑后，预期只剩 raw +0.02~0.06，且几乎都在 ≤20 件的房间，S1 之后的增益更小。

- 含义：大房间里模型面对的是一个用这些尺寸可能根本摆不下的题，模型能力不是唯一瓶颈。

**D. 免费确定性求解器作为 S1 之后的一级**（`polylayout-s2/`；`hdsl-local-regen/free-s2-checker/`）

规则：好物体当障碍，坏物体按占地从大到小逐个沿墙、沿法线、换墙重新锚定；尺寸、朝向、父物体、z 都不变；每件都放，找不到可行位置时取重叠最小的位置。

| 房间 | checker：S1 → +S2 → +S1 收尾 | strict | 平均耗时 |
|---|---:|---:|---:|
| 300 间 S1 后失败（全 test 抽样） | 0 → 0.577 → 0.640 | 0.007 → 0.027 | 12 s |
| 其中 1–10 件 | 0 → 0.642 | 0.021 → 0.042 | 3 s |
| 其中 51+ 件 | 0 → 0.565 | 0 → 0 | 42 s |
| API 探针选中的 100 间（11–50 件） | 0 → 0.690 → 0.740 | 0.010 → 0.040 | 0.6 s |

那 100 间的代价：
- GT 关系（`on` + 靠墙）保持率从 0.617 降到 0.590。
- 平均移动 18% 的物体，被移动物体中位位移 0.60 m，p90 3.0 m。

**E. Roomer 式移动阶梯**（`roomer-ladder/`，120 间 S1 后失败）
- 加入 0.05–1.2 m 的局部移动和 0.2 m 全房网格后，checker 修好 33%。
- 只用 S1 自己的候选重跑是 0.8%。

**F. LabBuilder 式门可达修复**（`labbuilder-nav-repair/a3only/`）
- 对象：S1 后只剩可达性问题的 307 间房，修好 46%。
- 全 test strict 实测 +0.016，上限 +0.036。没有任何房间变差。

**G. 掩码重填的启发式下限**（`p36-mask-inpaint/`）
- 对象：2,225 间 S1 后失败的房。随机均匀候选把被掩码物体逐个重放，checker 0.71。
- 但平均只放下 88% 的物体，违反“一件都不能丢”，只能当下限参考。

## 4. 不建议投入

- **DPO 再改一版**（op-DPO2 加关系过滤）：两位质疑者驳回。S1 本身不会破坏靠墙和 `on` 关系，关系保持下降是训练造成的，过滤配对解决不了。
- **训练 27B 做“看违规报告再改”的第二轮**：两位质疑者驳回。可用的训练目标太少，实际修复率估计只有 5–12%。
- **只加实例编号或解码禁重复**：上限只有 raw +0.012 / S1 后 +0.039（见 2B）。只作为别的改动的附带项。
- **跨模型蒸馏、best-of-8、联合预测尺寸**：之前已测，无效或很小。
- 文献表 70 条里 41 条与放置器无关：任务前端、桌面、real2sim、平台类。它们对 WorldEdge 世界层有用，对 FastFill 没有可拿的组件。

## 9. 上限实验：只缩尺寸能否让 GT 摆法放得下（2026-10-21，负面结果）
