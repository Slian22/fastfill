## 3. 当前精确指标声明：公式、分母、缺失性

记全部冻结请求为 \(U\)，房间 \(r\) 有 \(m_r\) 个可移动物体，臂 \(a\in\{J,P\}\)。\(C_a\) 是该臂成功解析、通过严格输出合同且完成评分的房间集合。这里 `complete` 还会因评分阶段捕获的错误为假，因此宜称“完整可评分输出率”，不能未经错误台账核对就等同于纯 JSON 解析率。\(C=C_J\cap C_P\)，标量另要求两侧该字段非空。

| 指标/字段 | 精确定义与方向 | 汇总分母及失败处理 | 能支持的解释 |
|---|---|---|---|
| `complete_rate` | \(\sum_{r\in U}1(r\in C_a)/|U|\)，越大越好 | 所有冻结请求；失败为 0 | 严格合同下的完整可评分输出能力 |
| `mean_id_coverage` | 每房间可解析输出中正确 ID 集合占预期 ID 数的比例，再对房间平均 | 所有请求；不可解析为 0 | ID 覆盖诊断；不保证其他字段有效，也不惩罚所有额外 ID 情形 |
| `geometry_success_rate` | 完整输出且无实现定义的越界、支撑失败、穿顶、main/severe 碰撞、固定阻挡 | 所有请求；失败为 0 | 带容差和豁免规则的包围盒通过率 |
| `oor` | \(O_{ar}=\frac{\sum_{i<j}|B_{ari}\cap B_{arj}|}{\sum_i|B_{ari}|}\)，越小越好 | 每房间算面积比，再对 \(C_a\) 房间等权平均；缺失不填 0 | 轴对齐 XY 两两重叠面积代理；不是越界率、碰撞房间率或 IoU |
| `size_iou` | 每物体 \(I=\prod_{k=1}^3\min(d_k,\hat d_k)\)，\(I/(\prod_kd_k+\prod_k\hat d_k-I)\)；先物体平均再房间平均，越大越好 | \(C_a\)，每房间等权，不按总物体数加权 | 同 ID、同轴、假定共中心的尺寸体积一致性；不是预测位置上的空间 3D IoU |
| `size_log_mae` | \(L_{ar}=\frac1{3m_r}\sum_{i,k}|\ln(d_{rik}/\hat d_{arik})|\)，越小越好 | \(C_a\)，缺失不填 0 | 相对尺度误差，天然对倍增/减半对称；不是米制 MAE |
| `parent_accuracy` | 每房间 \(m_r^{-1}\sum_i1(p_{ri}=\hat p_{ari})\)，再房间平均 | \(C_a\) | 参考父标签一致性；地面标签占比及多种可行支撑会影响解释 |
| `oor_repaired`、`geometry_success_repaired_rate` | 预测尺寸保持不变，位置边界修复后重算 | 前者完整可评分输出；后者所有请求 | 后处理辅助结果，必须与 raw 分开；10 cm 声明存在第 8 节问题 |

实现依据：[geometry.py](../../../../fastfill/comparison/geometry.py) `dimensions/geometry/score/aggregate`；[validate.py](../../../../fastfill/validate.py) `check/support_ok`；[evaluate_pair.py](../../../../fastfill/comparison/evaluate_pair.py) `metric_contract`。

**OOR 的精确定义应优先于中文名称。** 它只包含可移动物体，无高度/朝向区分，支撑堆叠仍可能贡献 XY 重叠，不含固定物体阻挡。它不一定在 [0,1]：\(m\) 个完全重合等面积框的值为 \((m-1)/2\)。跨房间的当前估计是房间面积比的均值，不是把全部面积先相加再做全局比值。该公式与原论文附录 D.2 相符，不代表其他物理指标也与原论文等价。

**几何通过率的限定必须跟着表头/脚注。** 当前边界检查仅适用于 `polygon/hull`，容差 10 cm；支撑采用底面到父顶面/地面高度误差及中心到父 footprint 距离不超过约 5 cm，父对象包含 movable 和 fixed，缺失父 ID 仍失败。它不要求整个子物体底面被支撑。未知高度不检查穿顶。碰撞使用有朝向 footprint 和高度交叠，面积阈值 0.01 m²、高度容差 5 cm，忽略特定平坦/小于 6 cm 高物体、支撑对、部分 tuck/contained；固定窗体阻挡另有豁免。应列 boundary type/height-known 的资格数量，不将未检查项称为通过。当前 `score` 清空 `constraints`，没有一般 `near/faces/between` 约束成功率，故不能声称已测语义约束遵循或网格动力学可行性。

**P 无 GT 尺寸回填的局部核验通过。** `score` 的 P 尺寸来自冻结 request 的 `objects[].size`，J 尺寸来自其输出；固定物体、边界、高度来自实际 request。GT movable 尺寸只用于尺寸诊断，GT 父标签只用于父标签诊断，修复使用预测/先验尺寸。该模块检查请求恰好两条输入消息。此结论局限于评分路径；它不独立证明上游先验拟合池无 test 泄漏、原始场景准入不依赖 GT，或通用预训练无污染。协议已正确保留这些上游边界。

### 3.1 不同分母之间不能借用差值或 CI

各臂公布的条件均值是 \(\bar y_a^{own}=|C_a|^{-1}\sum_{r\in C_a}y_{ar}\)。当前 paired 标量估计是

\[
\Delta_{micro}=|C|^{-1}\sum_{r\in C}(y_{Jr}-y_{Pr}).
\]

一般而言，\(\bar y_J^{own}-\bar y_P^{own}\ne\Delta_{micro}\)。因此 `summary.paired[field].ci95` 只能附给共同完整配对房间差值；不能附到各臂自有成功子集均值的相减上。率指标则使用所有请求的配对 0/1 差值。失败必须以请求数、失败数及原因显示；不填零的条件均值也不能被解释为缺失无偏。比如更困难房间更易失败时，共同成功子集本身会更容易。

完整率/几何率使用失败为 0，是明确定义的全请求二元终点；OOR/尺寸/FID/GPT 的缺失填 0 则会改变终点甚至奖励失败。两者不能混为一条“缺失统一补零”的规则。

## 4. 未知尺寸中的缩小漏洞与多有效解

合成例：两把椅子的中心相距 0.75 m，尺寸均为 1×1×1 m，原 OOR=0.125；位置不变、尺寸均减半后，OOR=0，尺寸 IoU=0.125，log MAE=ln 2≈0.6931。此例已调用当前模块验证，**不涉及任何新模型结果**。缩小并非所有场景中都单调降低 OOR，但足以证明“较低 OOR”不蕴含更合理的家具尺度；碰撞面积阈值和几何通过率也不能独立阻止此行为。

因此维持既有的 OOR、尺寸诊断、全请求可靠性并列，不在结果出来后给它们选权重或添加一个有利于某臂的综合分。未来若要认定功能性改善，需要独立冻结的尺度/功能验证与人工证据；本轮不能用 GT 尺寸替换 J 的预测尺寸再把那个 OOR 冒充 raw 端点。

尺寸 IoU/log MAE 同样不是未知尺寸任务的唯一真值：类别与房间可以允许多个合理家具规格；同类实例之间也可能存在合理的规格交换。当前按绑定 ID 比较一个参考实例，且轴对应固定，合理的规格或轴/朝向替代会受罚。高分说明更接近历史参考尺度，不自动说明更实用；低分也不自动说明错误。父标签准确率有类似多解及地面多数类问题。原论文附录 D.3 明确以合理、功能性布局而非精确复现 GT 为目标；这是解释参考诊断的边界，不是取消尺寸诊断的理由。[本地原文附录 D.3](../../../../tmp/pdfs/optiscene-paper/paper.txt)。

## 5. 18 来源 micro/macro 与配对连通组 bootstrap

`summarize` 的 micro 是房间等权，因此大来源影响更大。其各臂 source macro 是“先对每来源求同一指标，再对有值的来源等权”；标量有效来源可能少于 18，也可能两臂不同，必须同时报告 `<metric>_sources`，不能笼统写“18 来源宏平均”。率指标在每来源都有请求时保留所有来源。

配对 macro 则定义在共同可评分配对来源集合 \(S_C\)：

\[
\Delta_{macro}=\frac1{|S_C|}\sum_{s\in S_C}\frac1{|C_s|}\sum_{r\in C_s}(y_{Jr}-y_{Pr}).
\]

它与两臂各自 source macro 的相减也不必相等。这里的 macro 是**这些固定历史来源等权**的估计，不是对未知新来源随机抽样后的泛化保证。

当前 [geometry.py](../../../../fastfill/comparison/geometry.py) `paired_intervals` 的设计正确保留此前修复要求：

1. 用全部冻结请求、两臂相同 UID/source/group 建立房屋/别名连通组；跨来源组的签名是该组涉及的全部来源集合，先冻结再过滤指标。覆盖不一致、重复 UID 或组/来源不一致会拒绝。
2. 在每个完整来源签名层内，对连通组有放回抽取相同组数，保留整个组中所有来源/房间；两臂共享组抽样权重，不把对象、视图或同屋房间当独立样本。
3. 某组对某标量零观测仍参与抽样。令抽中次数为 \(M_g\)，则 micro draw 为 \(\sum_gM_g\sum_{r\in C_g}d_r/\sum_gM_g|C_g|\)，不是平均各组均值。macro 在同一 draw 按固定 \(S_C\) 对来源均值等权。
4. micro draw 无观察或 macro draw 丢失任一原有效来源时记 undefined；不会临时缩小来源集合。记录 `components/data_qualified_components`、`source_universe/data_qualified_sources`、`paired_rooms_by_source` 及有效/未定义抽样数。
5. 默认 2000 draws、seed 42，CI 为已定义 draws 的 2.5/97.5 百分位；少于 max(100, ceil(0.95×draws)) 个有效 draw 不提供 CI。2000 次时阈值为 1900。此阈值是数值报告保护，**不是覆盖率证明**。

单组签名层在 bootstrap 中没有组间变化；实现发出 `singleton_source_signature_strata`。即使给出窄 CI，甚至 [0,0]，也不得当作该层不确定性为零或结果确定。undefined draws 被剔除时区间条件于“有定义的 draws”，应显示警告与数量；不能把该区间称完整无条件 95% 保证。跨组独立性、组标识正确性及组数充足是解释前提；本审计没有重建真实 8647 请求的别名图。一般聚类推断文献指出忽略组内相关会夸大精度，少组情形也有专门限制；本实现的具体覆盖率未由该文献或现有单元测试证明。[Cameron & Miller, 2015](https://cameron.econ.ucdavis.edu/research/Cameron_Miller_JHR_2015.pdf)。

**单训练 seed 与 bootstrap 是两个层次。** 当前区间只反映固定两套检查点、固定来源签名结构下的房间连通组重抽样；不包含训练初始化、数据次序、教师/先验估计重拟合、模型选择或裁判重复评分的方差。8647 请求不等于 8647 独立训练重复，2000 bootstrap draws 也不等于 2000 次独立实验。不得写“跨随机种子显著稳健”；多终点、六层和 18 来源的点态区间不提供家族整体错误率控制。[Bouthillier et al., 2021](https://arxiv.org/abs/2103.03098)。

`evaluate_pair` 已将 macro 与 paired CI 写入 summary；`final_tables` 把该 summary 完整附入 `results.json.geometry`，没有发现将 micro CI 错接给 macro 的代码。当前 Markdown 只展开 micro/逐来源，macro/配对区间留在 JSON；主论文应显式展示它们及警告，否则读者难以看见已计算的主要比较。

## 6. 条件视觉指标：FID、AI judge 与 UR

### 6.1 FID

[fid.py](../../../../fastfill/comparison/fid.py) 对每个六分层使用同一 reference/J/P 成功图像及特征交集 \(V_s\)，每房间每臂一个固定 512×512 RGB perspective，2048 维 `pytorch_fid:0.3.0:pool3`，固定权重 SHA。分别计算 J/reference 与 P/reference：

\[
\widehat{FID}=\|\hat\mu_a-\hat\mu_R\|^2+
\operatorname{tr}(\hat\Sigma_a+\hat\Sigma_R-2(\hat\Sigma_a^{1/2}\hat\Sigma_R\hat\Sigma_a^{1/2})^{1/2}).
\]

协方差为 ddof=1。代码以中心化矩阵 \(A=X_c/\sqrt{n-1},B=Y_c/\sqrt{m-1}\) 的 \(AB^T\) 奇异值和计算根号项，数学上等价，避免直接处理奇异 2048² 协方差，并未加 jitter 或假图。现有数值测试覆盖平移/尺度/不同 N/奇异情形；本次未发现该公式错误。

但数值可算不等于统计可靠。N<2 返回 null；N≥2 只是可计算下限。样本协方差秩最多 N−1，六层的小 N 远低于 2048 时仍可能有大估计误差。有限样本 FID 有偏且偏差依模型而变，同 N 不能消除它；低秩算法不产生无偏或稳定性的保证。[Chong & Forsyth, CVPR 2020](https://arxiv.org/abs/1911.07023)。当前没有 FID CI，不得套用几何 CI，也不能把六个 FID 平均为已测“总 FID”。

FID 的 N 是 \(|V_s|\)，与 OOR 的 \(|C_{a,s}|\)、完整率的 \(|U_s|\) 不同。当前表格已分列 `OOR_complete_n` 和 `FID_shared_n`，并说明条件性，此处没有发现混用分母。还应披露全部候选、参考资产合格、参考图成功、两臂渲染/特征失败和 shared N；`fid.counts.reference_eligible` **实际指通过检查的参考图像数**，不能误称 reference 资产合格数。

真实资产辅助可减少盒子代理带来的视觉偏差，但映射来自 GT 身份 sidecar，并按各自预测尺寸拉伸资产；它不是模型从未知输入成功检索了相同资产，也不是原论文 native-scale/Isaac 流程。不同失败率引起 shared cohort 选择；同交集保证两臂在同样图像房间上比较，不保证代表全部请求。`visual_cases.attach_predictions` 中任一臂失败会使整对不进入可渲染 cases，故不能把后续视觉缺失全归因于各臂自身渲染。

### 6.2 AI judge 与人的 UR

[visual_cases.py](../../../../fastfill/comparison/visual_cases.py) 在参考资格和预测之前按稳定规则预选每层最多 29 房间，6×29×2=348 为正式选定臂请求上限；资格失败保留，不替换。预算不是已评分数量。`judge_batch` 无自动重试或补样；按 `selected/runnable/launched/success/failed` 留账。每个成功样本有功能、布局、美学 0–10 分；overall 可选，禁止用前三项自行补值。

按臂/层的均值是该项非空成功分数的平均。`by_stratum[stratum][arm]` 为扁平 score 字段，附 requested/success/failed 和 `score_counts`，与约定一致。paired 为同 UID 两臂均 completed 且该分项均有值时的 J−P 均差；当前无 judge CI。API 成功率不是布局质量，某臂自有成功均值之差不是该配对差；overall 必须用其专属 count。

两张视图是一个房间的证据，不能充作两个独立样本。当前 `gpt-6.1-sol` 分数既不与论文 GPT-4o 数值可互换，也未经本任务人工标注校准。关于 LLM judge 的一手研究报告了位置、冗长度、自我偏好及推理局限；其文本聊天中的一致性不验证本项目视觉裁判。此处引用只支持应校准与保留局限，不能声称本裁判已证实具有同样偏差大小。[Zheng et al., 2023](https://arxiv.org/abs/2306.05685)。

**本实验人工 UR 未测，保持 null/not_measured。** 原论文 §4.1 写 50 scenes、每场景 5 位标注者、至少 3 位判断物理和语义有效；§4.2 又写每房型生成 50。Table 3 的 OptiScene 卧室/客厅/厨房/浴室为 **75%/50%/30%/45%**。若每层恰为 50 个二元场景，比例步长应为 2 个百分点，75% 和 45% 无对应整数场景数。原文的分母/汇总/取整规则因此有歧义；不能反推 37.5/22.5 个成功场景，也不能擅定 N=20、合并轮次或替作者解释舍入。引用时保留原百分比并注明歧义，不能用它构造二项 CI 或作为本实验自动通过率的对照分母。[本地原文 §4.1、§4.2、Table 3](../../../../tmp/pdfs/optiscene-paper/paper.txt)。

## 7. 公平基线、消融与可成立的增量贡献

当前控制的优点是同通用基座 revision、同 seed/epoch/优化配置、共同准入 UID、相同解码策略及冻结共享上下文计划；P 训练用按连通组 OOF 的类别×房型轴向 log-median 估计，测试用完整训练先验。它是**有训练数据支持的尺寸估计+布局基线**，不应写成已代表所有强两阶段方法，或原作者模型。

仍须披露两类未匹配因素。文档记载 prior pool=124843，而共同解码器准入训练为 98754（长度准入前 98923）；P 的先验有更大训练数据暴露。J/P 监督 token 分别 53,157,852/34,454,444，约 1.54 倍；共同 epoch/更新数不代表相同监督 token、FLOPs、墙钟或输出难度。两个系统的目标表达、尺寸条件及可行教师布局也可能随方案变化。仅此两臂不能把差异全部归因于“端到端联合预测”这一因素。

在不改变当前主端点、且不追加本轮作业的前提下，未来最小消融建议如下；须在观察对应新测试结果前另行冻结：

| 想支持的主张 | 最小必要控制 | 本轮尚不能替代它的证据 |
|---|---|---|
| 联合方案相对该 P0 的系统收益 | 保留当前 J0/P0 与全部失败/尺寸/几何权衡 | 单一 OOR 或训练 loss |
| 收益来自联合建模，而非数据/预算 | P 先验在相同 decoder pool 的敏感性对照；明确匹配数据暴露或计算预算，并说明目标/teacher 差异 | 同 UID/epoch 不足以控制 token 与额外先验数据 |
| 优于有竞争力的两阶段设计 | 预先选定一个更强、仅 train 拟合的上下文尺寸预测器+同 placement 训练流程 | 只胜类别/房型中位数先验 |
| 尺寸预测是瓶颈 | 另列 GT-size oracle 的布局诊断，标为额外信息条件，不保证各指标的数值上界 | 把 oracle 冒充 unknown-size 公平 baseline |
| 改善可跨训练随机性复现 | 多个独立训练 seed 的预先配对重复；所需数量/精度根据 dev 或先验方差设计 | 房间 bootstrap 或一个 seed 的窄 CI |
| DPO/偏好阶段有独立贡献 | 同一臂内 J0→J1、P0→P1，明确偏好来源/预算；保留 SFT 主端点 | 当前 SFT 比较，或 legacy 不同协议 DPO 的提升 |

最稳妥的贡献表述是：建立不向模型提供可移动目标尺寸的可审计 J/P 比较合同；处理连通组 OOF、失败分母、跨来源配对不确定性及同资产条件视觉评价；在这些限制下实测尺寸一致性与布局质量的权衡。工程严谨性可支撑可复现性贡献，但不是自动的新算法贡献；“首次”“SOTA”或方法新颖性排序需要独立文献对照，本次没有开展完整新颖性检索。

### P2-1：10 cm 修复声明没有约束子树累计位移

位置：[geometry.py:56–69](../../../../fastfill/comparison/geometry.py) `small_repair`；依赖 [interface.py:275–324](../../../../fastfill/interface.py) `_push`；声明还见 `geometry.py` 文件头、`evaluate_pair.py:139`、`final_tables.py:118`。

### P2-2：最终发布门禁把缺失分层观测数当作零

位置：[final_tables.py:44–70](../../../../fastfill/comparison/final_tables.py) `_verify/_rows`；现有 [test_final_tables.py:25–26](../../../../fastfill/comparison/tests/test_final_tables.py) fixture 已含触发输入。
