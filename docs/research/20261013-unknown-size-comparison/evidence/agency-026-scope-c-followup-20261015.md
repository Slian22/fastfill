## 3. 成本与规模描述需要限定

C 的 token 来自逐房 receipts（run `94483a3243a6`），这一点优于 A 的部分估算：

| 成功回答的记录用量 | ESC-STRICT | BIG | 比值 |
|---|---:|---:|---:|
| 输入 token | 1,019,849 | 1,515,348 | 67.30% |
| 输出 token | 196,703 | 224,099 | 87.77% |
| 推理 token（分项，不应另行重复加到账单） | 89,056 | 104,236 | 85.44% |

“输入 token 约为 67%”正确；不能等同“总费用为 67%”。仍需区分成功回答、传输尝试、失败用量、本地模型/S1/验证及兜底资源。C 的原始 `result.json` 记录 300 个回答、301 次调用账本记录；`api-errors.jsonl` 有一次 HTTP 520。QA 发现 `spatiallm:scene_002887::room_2` 两次 attempt 分别见 calls.jsonl 第 247、248 行，最终 receipt 只保留 attempt=2、calls=1；frontier 147 行按最终回答 tries 汇总，漏掉首次失败调用。该房属于 ESC-STRICT 升级集合，按全账本归集为 **196/301 次调用（减少34.884%）**，不是195/300；ESC-CHECK仍为63次。失败尝试 token/是否收费未知，表中 token 为成功回答的已记录用量。应按 UID 汇总完整账本并核对运行总量。开源 O2 的运行仍消耗 GPU 资源，不宜称零成本。

规模证据：≤20 件家具的 231 间，127 间升级（55.0%，少调用约45.0%）；21–50 件为 52/53 升级，>50 件为 16/16。大物体数房间高度依赖大模型这一判断有支持；物体数不能直接替代面积。卧室升级 75%，客厅 80%，因此“常见房间普遍节省一半以上调用”不成立。厨房、阳台、卫生间、车库的列出比例本身正确。
