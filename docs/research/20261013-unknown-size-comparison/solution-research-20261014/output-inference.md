### Takeaways for FastFill

- **Measure best-of-N before building anything, and expect it to stop helping in large rooms.** Our checker is exact and uses no GT, so selecting with it is a fair inference-time component. That avoids the verifier gap Large Language Monkeys describes. If a room passes with probability p per sample, best-of-N pass is the average of 1−(1−p)^N. Failure is about 1.0 for rooms with 51+ objects, so p≈0 there and N cannot help. Gains will come from rooms with 1–30 objects.
  - Rank samples by violation count rather than pass/fail, so the least-bad sample wins.
  - LLM baselines must get the same N. That is our LLM comparison protocol.
  - It may be possible to estimate pass@N offline from the DPO stage-1 own-samples **[unverified whether per-sample checker results were saved]**.
- **Checking each object while decoding is the only one-call method that hits collisions where they happen.** A room passes only if every pair is clean, so room-level resampling fails for dense rooms. Object-level SMC or backtracking handles this: when an object's `on` field closes, run the incremental box checker on its box against the boxes already placed, the floor polygon and the keep-outs. If it fails, resample only that object's `pos`/`yaw` tokens.
  - Size is generated before position, so size stays fixed. This directly blocks co-located duplicates such as two islands at one spot or a pile of microwaves.
  - The 8B-model SMC gain (0.063 → 0.419) is the closest evidence. It is from another domain and unverified for layouts.
  - Risks: objects late in the order get squeezed, and K particles cost K× compute.
- **We need a deterministic minimum-displacement repair as the last stage anyway**, because the backend rejects a room for any 1 mm outside or 1 cm into a door/window keep-out. Proposed formulation:
  - Minimise weighted squared movement, with these constraints:
    - pairwise separation on yaw-aligned footprints, with the separation axis chosen per pair by smaller penetration (VPSC-style)
    - footprint inside the floor polygon
    - clear of doors and windows
  - Supported children move rigidly with their parent. Tuck pairs are exempt. Category, size and yaw are fixed.
  - Failure mode: no solution exists when total footprint exceeds free floor area, as in the dense SAGE kitchens. Report those rooms as unsolved. Never drop or shrink objects (gpt-6.1-sol already shrinks footprints by 17%).
  - Check it on GT first. GT passes at 0.72; record how much the pass rate rises, how far objects move and how much relation scores change.
- **Don't use from-scratch solvers.** Holodeck DFS and Infinigen simulated annealing satisfy the checker by omitting or randomly placing objects: DRFR 0.55, 38.5 collisions per bedroom, IB 8.1. That breaks object-set preservation and destroys relations.
  - LayoutVLM's model-initialised optimisation is the closest analogue. Even so, CF 81.8 shows a soft DIoU loss does not reach zero collisions in dense scenes, so it still needs the hard projection above.
  - Our gross overlaps (80–92% of colliding pairs overlap more than 30% of the smaller footprint) will likely push physics settling to fling objects out of bounds **[my inference, unverified]**. QP repair handles large overlaps more predictably.
- **Feeding checker output back to the model has the strongest literature number (66.7% → 0%) but fits us worst.** That result came from a frontier agent writing a DSL. Our 8B SFT model was never trained to edit a layout, and our current harness feeds back only parser errors. A collision list can be very long (167 pairs in one SAGE kitchen), and the loop needs several calls.
  - A cheap upper-bound test is Qwen3.8-27B, which already passes 0.81 raw.
  - Every arm must get identical feedback rounds under the comparison protocol.
  - Grammar-constrained decoding should be switched on regardless: it removes parse failures (27B goes from 0.81 to 0.93 with only 2 parser repairs). It cannot fix collisions.
