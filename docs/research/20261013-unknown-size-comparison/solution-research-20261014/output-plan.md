**证据强度的总前提：**

- 文献结果几乎都来自 3D-FRONT 中物体数 ≤21 的房间。

## 0. 为什么未通过

"未通过"就是被冻结检查器（`/Users/slian/Desktop/3D/Worldedge/OptiScene/fastfill/validate.py` 的 `check`）判为不合法。按影响大小排：

1. **严重重叠是主因。** J/P 相对 GT 的差距约 70% 来自可移动物体之间的严重重叠，而且主要是同类物体被放到同一个位置。这类失败集中在两处：
   - 51 个以上物体的房间；
   - GT 本身几乎全合法的程序生成来源。
2. **出界。** 房间越大越容易出界。
3. **学到坏标注。** 约 28% 的 GT 本身不过检，模型学到了这些错误。
4. **尺寸。** 尺寸精度只到"类别×房型中位数"这个先验的水平。

我的推断 [未核实]：SFT 只有 token 交叉熵，没有任何几何信号。一次输出 50 多个物体时，模型里没有"哪里已经被占用"的表示，于是会反复写出同类物体最常见的那个位置。

另外要注意：检查器允许出界 10 cm，后端要求 1 mm / 1 cm。**过检查器不等于下游可用**，两个指标必须分开报告。

## 1. 失败类型 → 方案族

| 失败类型 | 首选方案族 | 次选 | 依据 |
|---|---|---|---|
| 同类叠放（同类物体同位） | 拒绝采样微调或 on-policy DPO，负样本里加"复制同类兄弟物体的位置" | 解码时逐物体检查并回溯；后处理把重复物体挪到最近的空位 | 重复/早停问题在 Pix2Seq 里出现过（[2109.10852](https://arxiv.org/abs/2109.10852)），属于检测领域；"复制兄弟位置"负样本是我的提议 |
| 多物体碰撞（51+ 物体） | 确定性最小位移修复，再加按检查器排序的训练 | 改序列顺序：parent 后面紧跟它的 children | LayoutVLM、CasaGPT、MetaSpatial |
| 出界 / 门窗禁区 | 确定性投影修复（必须做） | 在 GRPO 里加边界项 | 后端 1 mm / 1 cm 硬拒，只有后处理能保证 |

| 尺寸只到先验水平 | 不在输出端修。P 直接用先验；J 加尺寸门防止缩小 | Number Token Loss（[2411.02083](https://arxiv.org/abs/2411.02083)），没有布局实验 | ReSpace 出现过缩小作弊 [复核] |

## 3. 推荐路线与预注册实验（600 个 dev 房间）

**指标：**
- 检查器通过率；
- 下游可接受率：footprint 出界 >1 mm 或进入门窗禁区 >1 cm 就算拒；
- 尺寸偏差 B：每房平均 log(预测 footprint / GT footprint)；
- 位移 Δ：每个物体 XY 位移的中位数和 p95；
- 关系保持 R：沿用 v2 的关系指标；
- GPT 评分：随机抽 100 房，盲评成对比较。

**统计：** 通过率在 0.5 左右时标准误约 0.02。用 McNemar 或配对 bootstrap，可检测的差异约 0.04–0.05，更小的差异不下结论。先冻结记录当前的 dev 基线。以下所有实验都要你确认后再跑。

### 短期（1 天，不训练）

**S1：对 GT、J、P 现有的 dev 输出做修复。**
- 假设：大多数失败靠小位移就能修好。
- 成功标准：
  - GT 通过率 ≥0.90，且中位 Δ ≤0.05 m；
  - J/P 通过率绝对提升 ≥0.20；
  - 可行房里下游可接受率 ≥0.95；
  - 中位 Δ ≤0.15 m，p95 ≤0.6 m；
  - R 下降 ≤0.03；
  - GPT 盲评中，修复后的胜加平 ≥60%；
  - B 变化为 0（尺寸固定，作为 sanity check）。
- 无解房的比例单独报告。

**S2：约束解码 + best-of-8（T=0.7，按违规数选），选出的结果再接 S1 修复。**
- 预测：
  - 修复前的原始通过率提升 ≥0.08，主要来自 ≤30 物体的房间；
  - 51+ 物体房提升 <0.03。
- 成功标准：
  - 原始通过率提升 ≥0.08；
  - 再接 S1 修复后，下游可接受率比单独 S1 高 ≥0.03，且中位 Δ 下降。
- 每个样本的检查器结果都要保存下来。

**决策规则：**
- 如果 S1 能过检但需要很大的 Δ，说明问题是叠放，不是轻微擦碰，资源转向 M2。
- 如果 S1 的 Δ 小、R 不降，那么有效性问题主要由后处理承担，训练应该转去提升关系质量。

### 中期（1 周）

**M1：数据修复后重训 SFT。**
- 先拆解 GT 的失败：哪些是 tuck 或支撑的伪影，哪些是真碰撞。
- 合成来源：删掉失败的房间。
- 真实扫描和 3D-FRONT：只做 XY 平移修复，最大位移 ≤0.3 m，修不好就删。
- DPO 的 chosen 只用过检样本。
- 成功标准：
  - 原始通过率 ≥ 基线 +0.04，配对 CI 不含 0；
  - log 尺寸 MAE ≤0.29；
  - |B| ≤3%。

**M2：在 M1 模型上做 2–3 轮拒绝采样微调或 on-policy DPO。**
- 每个训练 prompt 采 K=8 个样本，只保留同时满足以下三条的：
  - 过检；
  - 每个物体的 log 尺寸误差不超过先验水平；
  - 物体集合与输入完全一致。
- 成功标准：
  - 原始通过率 ≥ M1 +0.10；
  - 同类同位的碰撞对减少 50%；
  - |B| ≤3%；
  - R 不降；
  - GPT 盲评胜率 ≥50%。

**M3（可选，和 M2 并行）：SMC 原型。**
- 只在 P 臂、31–50 物体的房间上试。
- 同等计算量下比 best-of-8 高 ≥0.10 才继续做。

### 长期

- **L1 GRPO：** 只有在 M2 之后，31 个以上物体的房间仍明显失败时才做。成功标准是不加修复时原始通过率 ≥0.65，且 R、B 和 GPT 评分都不比 M2 差。
- **L2 序列重排：** 如果 51+ 物体房的失败率仍接近 1.0 再做。
- **L3 扩散头：** 只有前面两条都停滞时才做。

## 4. 明确不推荐

1. **单纯加 GIoU/L1 去贴 GT 标注（v2 的路线）。** 生成任务里一个物体可以有多个合理位置，回归会把它们平均掉。v2 的关系分已经证明了这一点：0.25–0.43，GT 是 0.71。这样还会把 28% 的坏 GT 一起学进去，而且这种损失无法作用在文本 token 上。
2. **改数字的 tokenization。** 没有证据说明它能减少碰撞。对比的系统都用 2 位小数的 JSON。
3. **从零开始摆放的求解器**（Holodeck DFS、Infinigen 模拟退火）。它们会丢物体、破坏摆放关系：Holodeck 的 IB 只有 8.1 [复核]。
4. **二值通过奖励，或不带尺寸门的奖励。**
   - 51+ 物体的房间里几乎所有样本都失败，组内方差为零，没有梯度。
   - ReSpace 原文写明了缩小作弊 [复核]。floor-plan RLVR（[2605.14117](https://arxiv.org/abs/2605.14117)）的类似说法摘要里没有 [未核实]。
5. **一刀切删掉那 28% 的失败 GT。** 真实扫描几乎会被删光，而且主要差距本来就在 GT 合格的那些来源上。
6. **删物体、合并物体或缩尺寸来过检。** 违反物体集合和尺寸必须保持的约束。
7. **让 8B 模型多轮读检查器反馈自己改。** SG-Agent 的 66.7%→0% 是前沿大模型写 DSL 得到的（[2604.27555](https://arxiv.org/abs/2604.27555)）。我们的模型没学过编辑布局，这样做也违反一次调用的约束。最多拿它在 27B 上做上限对照。
8. **只优化碰撞，或用物理仿真沉降。** 只管碰撞会让出界变多；重叠很大时，物体可能被弹出房间 [推断]。

**怎么调研：** 先读 LayoutVLM、CasaGPT、MetaSpatial 和 ThinkBLOX 的消融，以及 ReSpace 的 A.2 节。然后跑 S1 和 S2，得到"修复上限"和"采样上限"，再决定把训练资源花在哪一端。
