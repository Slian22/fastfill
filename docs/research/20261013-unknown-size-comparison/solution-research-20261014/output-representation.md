Shared caveats:
- None of these papers reports a box-checker pass rate comparable to FastFill's 0.39 test pass rate.
- The gains are on rooms with fewer objects (3D-FRONT style). Our failures pile up in rooms with 51+ objects.

### Why multimodality matters

In detection, the right box is pinned down by the observation, so L1/GIoU regression to one target is fine. In generation, a sofa can go against any of several walls, and an L1-trained regressor puts it at the average of those spots. That fits v2's sizes being fine while its arrangement scored like shuffled GT. ATISS (mixtures) and DiffuScene/PhyScene (diffusion) avoid this by modelling the full distribution. The current LLM does too, because it generates autoregressively. So the fix belongs in a **reward or guidance on samples**, not in a regression loss on the mean.

### Expected gain and compute for Qwen3-8B LoRA *(my estimates, unverified)*

- **Checker-ranked online DPO:** k=8 samples per room. Chosen = best checker score that passes a size guard; rejected = worst. Cost is similar to OptiScene, about 100–150 GPU-h.
- **GRPO with a dense checker reward:** G=8, about 500–1000 steps, rollouts up to about 4k tokens for large rooms. Roughly 150–400 GH200-hours. Rollout generation dominates; the checker is cheap on CPU.
- **Plausible gain:** +0.08–0.20 absolute pass rate. The anchor is MetaSpatial 7B's collision 38%→12%. ReSpace's null human-preference result is the downside case.

### Takeaways for FastFill

- **Reward hacking will hit arm J first, so guard size from the start.** Two papers saw shrinking hacks as soon as the reward ignored size (ReSpace: objects; floor-plan RLVR: rooms), and gpt-6.1-sol already shrinks footprints by 17%. For arm P, force sizes to the prior and score only position, yaw and support, which makes shrinking impossible. For arm J, gate the reward on per-object log-size error staying within the prior's level (about 0.29, so J can't do worse than the median prior). Also reward-gate the object set: exact count, categories and ids, which stops the model from dropping or merging duplicates. Track footprint ratio as a separate held-out metric.
- **Use a dense, per-pair reward rather than binary pass.** In rooms with 51+ objects almost every sample fails, so a pass/fail GRPO group has zero variance and gives no gradient. Score the fraction of colliding pairs (or overlap/min-footprint), OOB distance with tanh or exp shaping (ThinkBLOX, SPG), support error, and door keep-out. Normalize each tier separately as in GDPO; ThinkBLOX shows plain GRPO with a summed reward trades boundary and PSA away for collisions. MetaSpatial's penalties on coordinate tokens fit our id/size/pos/yaw output order, so blame can land on the objects that actually collide.
- **Replace OptiScene stage 2 with on-policy, checker-ranked pairs.** Synthetic perturbations of GT are off-policy and don't contain our real failure: co-located duplicates. Pairs built from the model's own samples ranked by the checker do contain it. This is the cheapest next step, and the regularised RPO run (0.41→0.47) already shows DPO helps on this data. Drop GT rooms that fail the checker (about 28%) from the "chosen" pool, or the model keeps learning to copy their errors.
- **Differentiable geometry losses don't attach to text tokens.** The only training-time route is a Number-Token-Loss-style surrogate (unproven for layouts). The inference-time route is a LayoutVLM/PhyScene-style DIoU projected-GD repair after the single LLM call. It can enforce the backend's 1 mm footprint / 1 cm keep-out rules exactly, without retraining. Optimize collision, wall and door terms jointly, because PhyScene shows collision-only guidance raises out-of-room rates (0.24→0.35).
- **Curriculum by object count, and evaluate on more than the checker.** Train RL on rooms with fewer than 20 objects first, then add larger ones. The training reward and the test metric are the same frozen checker, so also report GT-relation metrics, size MAE and footprint ratio to catch overfitting to the checker.
