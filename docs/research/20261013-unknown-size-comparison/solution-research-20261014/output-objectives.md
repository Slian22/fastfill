## 数据侧修复：文献调研（FastFill，bbox → 输出端）

**为什么 GT 本身过不了门。** 本仓库日志 `docs/research/20261013-unknown-size-comparison/research-log.md`（commit 1f1d1fcc6）记录了测试集各来源的 GT 门通过率：ScanNet 0.135，3RScan 0.171，3D-FRONT 0.494，HSSD 0.529，ARKit 0.576，Structured3D 0.621，SceneSmith 0.780，SAGE 0.869，InternScenes_gen 0.962，MansionWorld 0.976，holodeck 1.000。v3 数据"只打标记不过滤"，所以训练集里包含不合格的标注。不过 J/P 超出 GT 的那部分失败，约 73–75% 来自 GT 几乎全合格的多物体合成来源。因此，单靠清洗数据最多只能补上约 1/4 的差距。

### 对 FastFill 的要点

1. **不要直接删掉那 28%，要按来源分别处理。** ScanNet 和 3RScan 的 GT 约 83–87% 不合格，一刀切删除几乎会抹掉真实扫描的覆盖。更大的问题是，这样做打不到主要差距，因为主要差距来自 GT 合格的多物体合成房间。建议分两类：
   - **合成和设计师来源**：直接剔除失败房间，损失很小。
   - **真实扫描和 3D-FRONT**：照 CasaGPT 的做法离线修复。只做 XY 平移，不改尺寸和 yaw（PhyScene 发现引导尺寸会把物体压薄，这和 gpt-6.1 把家具缩小 17% 的偏差是同一个方向）。优化目标就是冻结 checker 的项：先修越界和门窗禁区，因为下游后端在 1 mm / 1 cm 处会硬拒；碰撞其次。只有当最大位移不超过约 0.3 m（阈值待定）且修复后过门，才采用修复结果，否则丢弃该房间。
   - 尺寸统计继续用原始数据，因为平移修复不影响尺寸先验。
2. **"修 bbox 与输出端"最便宜的杠杆是拒绝采样微调，而不是继续调 DPO。** 做法是：对训练 prompt 采样 K 个输出，用 checker 过滤，再并回 SFT 迭代 2–3 轮。CasaGPT 用这个方法 3 轮把 NIRate 提高了 14–33 个百分点，而且完全符合"单次调用、JSON 文本输出"的形式。同时需要检查 DPO 的 chosen 样本：stage-1 若用失败 GT 当 chosen，等于在奖励碰撞，应改成"过门的 GT 或过门的自身样本"。
3. **区分"包围盒重叠"和"真实碰撞"。** CasaGPT 和 ReSpace 都明确指出，桌下椅子、架上物品属于合理的包围盒重叠。改动数据之前，先按来源和违规类型拆解 GT 失败：如果只是类似塞入（tuck）的重叠，或者是有 support parent 的叠放，应扩充 checker 的豁免表并另外报告，而不是去修数据。这一步也决定了 0.72 的 GT 上限有多少是 checker 本身的伪影。
4. **专门增广多物体、重复类别的房间。** 失败率从 1–5 个物体时的约 0.32 升到 51 个以上时的约 1.0，失败对大多是同类重复物体叠在同一位置。可以用 Holodeck 或 SceneSmith 这类约束求解器批量生成含 N 个同类物体的大房间，GT 天然合法，并在采样中提高这类来源的权重，而不是降低。按物体数做 curriculum 没有布局领域的先例，只能作为可选实验。
5. **不想删数据时，可以用质量标签做条件。** 在 prompt 中加入 `[gate:pass]` 或 `[gate:fail]`，推理时固定用 pass；也可以只对违规物体的 token 做 loss mask。这样能保留真实扫描的覆盖，但思路借自 NLP 的 [Quark 2205.13636](https://arxiv.org/abs/2205.13636) 和 [SteerLM 2310.05344](https://arxiv.org/abs/2310.05344)，布局任务上没有验证过。最低成本的验证顺序是：先只用过门 GT 训练 SFT，测通过率的变化；再试修复版；最后试拒绝采样微调。
