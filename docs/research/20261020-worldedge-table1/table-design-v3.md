## 1. 表 A：生成的完整世界能否支持固定 Agent？

| 列组 | 主表列 | 回答的问题 |
|---|---|---|
| 世界交付 | Load ↑ | 请求的世界有多少能导入统一模拟器？ |
| 语义与空间关系 | CNT ↑、ATR ↑、OORel ↑、OARel ↑ | 数量、属性、物体间关系、物体与建筑关系是否符合要求？ |
| 物理质量 | COL ↓、STB ↑ | 是否过量穿透；短时物理仿真后是否稳定？ |
| 全局可达 | Reach ↑ | 固定机器人起点能否经连通路径抵达任务目标的合法接近区域？ |
| Agent 任务 | **E2E SR_C ↑［95% CI］**、GC_C ↑ | 整个请求最终成功多少；带身份/时序约束的目标完成多少？ |

候选方法行：SceneSmith、EmbodiedGen V2、SceneCode、EmbodiedSmith、Code2Worlds-2、WorldEdge。前五个是待适配候选，不能把论文原始分数搬来。以实际共同支持的房间规模、任务、动作与模拟器接口冻结比较范围；未通过适配审查的配置公开排除，不填零分。

C 包含导航、局部交互/关节操作和跨房间任务的预定分层；某类任务没有共同支持时，应在跑分前缩小共同集或另设子集，不混算。若需要新增多房间组装器、关节生成器或状态宿主，方法名称必须包含这些适配组件；不能称为纯格式转换。

Load 以全部世界请求为分母；其余世界质量以全部已加载世界评估，包含未通过后续接纳检查的世界，并公开每列样本数。E2E SR_C 以预注册任务执行槽位为分母，确认的生成/导入失败不能剔除。Reach 是几何代理指标，不能当机器人导航成功。

## 2. 表 B：世界增长时，旧状态和任务还能否成立？

| 列组 | 主表列 | 判定方式 |
|---|---|---|
| 扩展交付 | Expand_g ↑ | 一条诊断序列的全部 g 次新增区域都交付、可加载、满足结构要求且正确连接 |
| 扩展与状态 | Expand+Keep_g ↑ | 全部扩展有效，且每个扩展边界都保留所有受保护的历史状态 |
| 扩展后的世界 | Reach ↑、COL_Δ ↓、STB_Δ ↑ | 最终要求的目标是否可达；新增区域和受影响边界是否碰撞、稳定 |
| Agent 任务 | **E2E SR_G ↑［95% CI］**、GC_G ↑ | 实际完成依赖扩展前状态与扩展后空间的任务；这是主结论 |
| 系统资源 | Time/seq（秒）、Peak sim. RAM（GiB） | 每条诊断序列的生成/扩展处理耗时；模拟器及状态工作进程的峰值内存 |

表 B 从相同合法起始世界开始。各在线策略用相同资产池、当前请求、状态读取接口和预算；未来请求按时释放。它测试增长机制，因此初始种子世界构建不计入 B 在线方法的得分/耗时，另公开其生成方式与成本。C 则从完整世界生成请求起算，二者不能合成总分。

| 方法行 | 作用 | 公平性要求 |
|---|---|---|
| 程序化追加＋正常持久化 | 简单但可执行的独立扩展对照 | 保留正常保存和恢复能力；公开房间模板/语法 |
| 全量重生成＋状态恢复 | 有竞争力的独立对照 | 提供操作后的当前状态，允许合格的身份映射和状态恢复 |
| **WorldEdge 完整系统** | 待检验方案 | 使用同样执行器、资产和预算 |
| WorldEdge 去布局优化；去状态保持验证 | 两个独立消融行 | 只关闭对应组件；普通保存/恢复保留。具体模块映射在实验前固定 |
| 一次预生成＋逐步开放 | 单列的离线参照 | 生成器提前知道完整请求；Agent 不知道未来。计入完整预生成耗时，不参加在线扩展成功率排名 |

拟议主设置为 **2 个初始房间＋4 次各增加 1 房间，即 g=4**。先用独立 pilot 验证控制器、适配和计算预算，再冻结。完整 Agent 成功要求全部 g 次扩展有效及全部任务约束通过；主任务卡还要求每个新增房间贡献一个必要目标、物体或依赖，并在最后一次扩展后使用早期改动过的实体。扩展次数 1/2/4/8 的独立曲线放配套图；不能将有限规模试验解释为无界可靠性。

## 3. 最关键的计分规则

1. **扩展率按整条序列算。** 计划扩展 4 次，第 2 次确认失败，该序列就失败。记录停止位置和未尝试后缀，不把后两次从分母删掉。Expand+Keep ≤ Expand；另报“完整扩展有效时的条件保持率”。
2. **世界探针与 Agent 执行分开。** 状态诊断使用 reset 副本和固定合法探针；允许明确披露的状态编辑来隔离保持能力。真正的 Agent 任务必须实际执行动作。两类试验不是同一分母，不能相乘得出任务成功率。
3. **目标与历史不可改写。** 比较同一杯子、抽屉、位姿、关节、包含关系和顺序；不能生成替代物、提前完成目标或简化任务。物理暂停/继续规则固定，正常动力学变化不算状态损坏。
4. **失败与未知分开。** 确认的系统失败保留在分母；执行中途失败仍保留按冻结约束验收的部分目标进展。成功率未知案例报告识别区间；GC 也报告区间：已知进展和为 Q、未知值有 U 个、总槽位 N 时，为 [Q/N, (Q+U)/N]。质量指标公开条件分母和缺失数；碰撞/稳定性不为加载失败编造好分。按独立世界/任务序列做配对置信区间。
5. **资源包含失败和重试。** 主表耗时是实际处理资源，不是成功完成延迟；另报超时率及成功延迟。早失败的低耗时不算效率优势。模拟器 RAM 不冒充包含远端模型的总内存，完整 CPU/GPU/API 成本单列。

G 的世界诊断在失败前最后合法快照上检查全部最终要求目标，缺失房间/对象记不可达。COL_Δ/STB_Δ 只观察已加载检查点的新增物体及预定义边界对象，先在序列内汇总，再跨序列平均；公开覆盖率并配合 Expand 解读。完整世界和旧区域的质量分数仍需附报，防止平均值掩盖局部破坏。

状态探针要先验证合法性。初始化失败、扩展失败、扩展成功但旧状态损坏分别记录；不能只挑容易成功的探针。G 实际任务中由 Agent 执行初始操作，其失败同样属于整条任务失败。

## 4. 配套结果各承担什么

| 配套项 | 必要内容 |
|---|---|
| 完整世界诊断表 | OOB、ACC、房间/门拓扑、关节扫掠空间、完整语义分项、视觉/提示忠实度 |
| 增长曲线 | g=1/2/4/8 下 SR_G、Expand、Expand+Keep、耗时、内存；同时报房间数、物体数、面积/密度 |
| 状态与任务分层表 | ID/位姿/关节/包含关系损坏；导航、抓取放置、关节操作、跨房间和回访结果 |
| 完整记账表 | 请求、加载、探针初始化、尝试扩展、实际执行、成功、确认失败、未知；延迟、超时、成本及样本数 |
| 恢复控制与能力矩阵 | reload-only 与真实增建分开；Oneira、Genie/SIMA、AgentOdyssey 等先例列出机制与执行抽象，不强行混入同一个物理数值榜 |

完整表 A 验证“世界可用”；表 B 的 SR_G 验证“增长中能做任务”；Expand+Keep 和资源曲线解释原因及代价。世界指标不合成未经验证的总质量分，C/G 也不做混合总平均。

## 5. 第一个可判别任务

固定执行器把指定杯子放进 A 房间的指定抽屉并关上 → 增建连接的 B 房间和目标台面 → 返回 A 打开同一抽屉 → 取出同一杯子送到 B。验收包含真实动作、身份、顺序、物理终态与驻留时间。

这只是一轮扩展的最小例，不等于完整 g=4 任务。先运行这一例与“全量重生成＋状态恢复”对照，确认世界状态和执行验收链条接通，再开展 g=4 的配对试验。各方法初始状态相同，后续读取各自实际演化后的状态；不为保持中间状态一致而强行 reset。单例成功证明可运行，不能填成可靠性结论。当前本地已完成的布局/视觉/符号结果仍不能直接填入新表。
