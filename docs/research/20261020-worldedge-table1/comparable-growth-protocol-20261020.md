# 可扩展 3D 任务：可比较的指标与实验协议

日期：2026-10-20。状态：设计稿；不是已运行 benchmark。继承[大表 v4](table-design-v4.md)的分母、unknown、物理阈值和独立执行器规定，本文件补充外部方法适配、指标验证与实验启动条件。最终表格入口见 [README](README.md)。

**可以定义新的联合任务和指标，不必先证明无人做过。** 新指标须对方法实现中立、可由独立证据判定，并能够检出明确失败。贡献最终由方法、任务难度和公平实测建立，不能由改名或更长的限定词建立。

## 1. 研究问题与表格保持一致

研究问题：当任务所需的新空间逐轮交付时，系统能否保留 Agent 已改变的物理状态，让固定执行器完成依赖这些状态的后续任务？

已有 [HappyWorld-Bench Table 12 / B.6](https://arxiv.org/html/2609.24308v1#A2.SS6)评扩展与区域保持；[SceneSmith App. L](https://arxiv.org/html/2602.09153v2#A12)评生成场景中的机器人任务；[PARTNR A.5](https://arxiv.org/html/2411.00081v1#A5)提供有依赖的任务评价。我们组合并具体化自己的物理任务协议，不将这些方向称为首次。

| 表格部分 | 要比较什么 | 不同方法如何参加 |
|---|---|---|
| A：有限世界 C | 完整生成系统交付的世界质量与固定执行器任务成功 | 外部系统使用共同任务规格、已验收的格式适配、相同模拟器/执行器；各自生成能力是比较对象 |
| B：扩展任务 G，系统对比 | 在相同初始状态和逐轮请求下，具体系统配置的任务可靠性与成本 | 原生扩展，或外部生成器＋公开的增长适配器；明确适配器也是被测系统的一部分 |
| B：扩展任务 G，机制对照 | 在相同生成组件与任务关键资产下，增量更新相对重生成的差异 | 固定组件，只改变增长/恢复策略；与不同生成器的系统对比区分解释 |

主 G 实验在扩展边界暂停物理时钟，完成生成、加载和状态验收后再继续执行；这个同步协议不支持“机器人不停运动时热更新”的主张。若研究异步更新，需要另外定义真实时间动力学与延迟协议。

## 2. 自定义核心保持少而明确

世界诊断 cohort 用固定合法状态探针；Agent cohort 使用真实动作。两者分别计分，不能将两个边际率相乘。

| 指标 | 定义与分母 | 为什么需要 |
|---|---|---|
| **Expand_g** | 全部 g 次扩展均在预算内交付、能加载、满足新增空间/接口规格且正确连接的诊断序列数 ÷ 全部预定诊断序列数 | 排除不扩展、只改标签、扩到一半就停止；与状态保持分开 |
| **Expand+Keep_g** | 全部扩展有效，且每个边界的全部受保护状态均通过的诊断序列数 ÷ 同一总序列数 | 既扩成功又保住旧状态；不会因只保留容易对象而高分 |
| **E2E SR_G**（主终点） | 全部 g 次扩展有效且全部任务目标、身份、时序及保护条件通过的执行槽位数 ÷ 全部预定执行槽位数 | 衡量完整系统真正做成任务的比例，包含扩展和执行失败 |
| **GC_G**（辅助） | 每个执行槽位在完整目标集合上的约束感知完成率，再跨全部槽位平均 | 定位部分完成；未生成/未激活的目标不能从分母删除 |
| **Time/seq、Peak sim. RAM** | 延用 v4 明确的处理时间与模拟器内存范围，包含失败和重试 | 描述代价；不能用早失败产生的低成本宣称更高效率 |

这里 Expand 和联合保持是自定义序列协议；SR/GC 是已有任务度量在本设置中的改编。Load、CNT/ATR/OORel/OARel、COL/STB、Reach 继续采用已有文献定义及 v4 披露的改编，不再发明一套总质量分。

令 a_jt 为第 t 次扩展交付通过，p_jt 为该边界状态保护通过，则 Expand_g = mean_j product_t(a_jt)，Expand+Keep_g = mean_j product_t(a_jt p_jt)。这是逐条序列求联合结果再平均，不是把均值相乘。已确认早失败使整序列失败，未尝试后缀不伪装成观测；未知结果保留识别区间。联合率应不超过扩展率。

条件保持率 P(全部保护通过 | 全部扩展通过) 放附表，并同时报告适用数。若某个追加方法天然固定旧状态，保持率达到 100% 是合理结果；由任务成功、新区质量和成本继续区分方法，不能修改指标让该基线失分。

### 独立证据及容差

判定读取**实际加载后的模拟器状态和执行轨迹**，不能只相信生成器返回的 `success`、计划 JSON 或未加载的快照。语义 ID 是跨重建的匹配键；模拟器内部索引可以改变，但不允许一对多替身或用同类新对象冒充原物体。

扩展前由独立评测器建立身份台账：每个语义 ID 唯一绑定源资产摘要、几何/碰撞体、尺度、关节拓扑、任务相关实例属性，以及实际物理状态。允许销毁后重实例化，只要逐项满足预定的重建等价关系且映射一一对应；源文件格式可转换，但其几何/物理等价须在适配验收时核实。仅沿用旧字符串 ID、换一个相似杯子不算同一对象。恢复器可以直接按台账重建旧资产与结构，不要求生成模型重新猜测。

每次请求还冻结允许变化的空间/属性范围：默认只允许新增区域及预先声明的连接口施工；旧区任务相关的碰撞几何、障碍、关节限制、质量/摩擦等参数不得随意改变。接口局部改动和无关视觉改动需预先列出允许项，不能由方法在看到结果后自行扩张。机器人位姿/速度/夹持状态与执行器记忆按同一暂停恢复契约保留，不以重置机器人或额外辅助降低难度。重新加载后的独立检查同时核对这些不变量。允许扩大新区，不允许偷偷移除旧障碍或关闭碰撞来提高任务成功。

冻结需保护的对象/关节/包含关系、坐标系、状态字段、每项容差和有效时间段。位姿容差按独立校准与任务所需精度确定；不得直接把 STB 的 1 cm / 0.1 rad 当作所有持久性谓词的默认容差。合法动力学变化不计破坏。碰撞与稳定性在 reset 副本上诊断，不能通过诊断过程把任务世界偷偷修好。

## 3. 别人的方法怎样接入增长任务

统一概念接口为 `grow(current_physical_state, released_request, budget) → candidate_world + id_mapping + event_log`。这只是实验契约，当前不宣称已有所有实现。

| 候选行 | 增长适配方式 | 能得出的结论 |
|---|---|---|
| **WorldEdge** | 原生增量生成、物化及持久状态处理 | 完整系统在指定接口和任务范围下的表现 |
| **SceneSmith + regenerate/restore** | 用当前已公开的完整规格生成目标世界；共享恢复器迁移已有语义 ID 与状态；计入完整生成和恢复成本 | 对此适配后的完整系统比较，不称为 SceneSmith 原论文结果 |
| **EmbodiedGen V2 + regenerate/restore** | 同上；需先确认场景导出、关节和当前任务交集 | 对此适配后的系统比较；也不等于其原生 Vibe Coding 的能力上限 |
| **固定 WorldEdge 组件 + full regeneration/restore** | 与增量系统使用相同生成组件、关键资产、输入与预算，只改更新策略 | 更直接检验增量策略的价值；这是机制对照，不冒充外部方法 |
| **Procedural append + persistence** | 使用已公开的程序模板追加合法区域，保留普通状态保存 | 独立简单对照；不故意关闭其持久化能力 |

两项 WorldEdge 消融仍保留；一次预生成＋逐步开放作为获得未来信息的离线参照，不能参与在线扩展率排名。表格空间不足时，将外部适配对比与机制对照分组展示，不能只留下自己的消融。

为何优先上述两个外部候选：[SceneSmith App. J](https://arxiv.org/html/2602.09153v2#A10)有多模拟器导出依据，[EmbodiedGen V2 §2.5–2.6](https://arxiv.org/html/2607.07459v3)有多房及状态式编辑依据；它们值得做接入审查，但这些文字不能代替适配验收。SceneCode、EmbodiedSmith、Code2Worlds-2 继续列在有限世界候选中，增长适配通过后才能增加对应增长行。

### 恢复器不能被故意做弱

统一提供旧对象的语义/资产 ID、坐标基准、关节和合法状态；允许直接映射，不能要求基线凭图像重新识别已有对象。恢复器须先通过无增长的保存—重建—恢复检查，覆盖本协议所有被评分字段；任何未支持项必须披露。移植后仍要检查碰撞、导航和任务条件，不能通过强制写状态制造穿透或预满足目标。

若某系统可原生局部编辑或支持“只生成新区＋通用拼接”，先记录为额外候选，不压制其更强接口。实现与调参预算相同并公开，在独立 pilot 中验收，再冻结配置。不能只挑最差适配来代表该方法，也不能用测试集挑最佳适配。

不能适配的配置标 `unsupported / not adapted`；进入正式试验后真实生成、加载或超时失败才按协议计失败。不能将“原方法不支持我们的接口”写成性能零分。

## 4. 公平性不要求所有东西都一样

| 固定的内容 | 为什么固定 |
|---|---|
| 输入任务、逐轮信息释放、世界/任务 seeds、总预算、重试规则 | 避免泄漏未来、改题、无限重试；所有确认失败留下记录 |
| 初始世界、对象身份、机器人的动作/观测权限和执行器版本 | 建立配对起点，不让一方使用额外动作辅助或状态信息 |
| 任务关键资产版本、尺寸、碰撞体、关节、物理参数（机制轨道） | 避免用更容易抓取/打开的资产替代增长机制提升 |
| 独立评测器、标注、容差、完整目标集合 | 防止方法自评、只对成功生成的内容计分 |
| 硬件/缓存状态、运行顺序与记录粒度 | 避免批次和热缓存与方法完全重合 |

完整生成系统轨道允许各自的非关键资产、生成模型与算法发挥作用，并列出差异与完整成本；不能一边宣称比较完整系统，一边只把某方替换成我们的资产生成链。机制轨道则尽量固定生成组件。两个范围分开解读，不把所有性能差都归因于扩展算法。

各方法从同一合法种子出发，后续读取自己的实际演化状态，不为了维持中间状态一致而强制 reset。种子接纳只看方法无关的初始可行性，公开拒绝和来源；只来自 WorldEdge 的种子只能支持该分布上的结论。

主要机制对照预定为固定组件的重生成＋合格恢复；外部系统对照是单独的完整系统比较。所有主要对比在正式数据采集前冻结，不能观察结果后改成最容易击败的方法。

## 5. 新指标如何证明不是偏向自己的计分器

这部分是评测器验收目录，尚未实现或执行。所有方法使用同一套，并独立于生成器进行。

| 控制或扰动 | 指标应有的反应 |
|---|---|
| **无操作/不扩展；只增加房间标签；输出不能加载** | Expand 与联合保持不能通过；完整任务失败；未观测 COL/STB 不赋好分 |
| **扩展有效但旧杯子位置、抽屉关节或包含关系被回滚** | Expand 可以通过；联合保持失败；依赖该状态的后续任务失败。不同字段逐一注入，不能只测整体重置 |
| **换同类对象、复制相同 ID、目标预先满足、跳过必需新房间；偷偷删除障碍/关闭碰撞** | 独立身份、初态、顺序、必要性或旧区物理不变量检查失败；沿用旧 ID 但换资产/实例属性仍失败 |
| **完全合法的扩展；合格重实例化/内部索引重排；允许容差内的数值误差** | 应通过对应检查；记录误报。与不合格替身成对检验，刚超过容差的受保护字段须被检出，做阈值敏感性检查 |
| **中途失败、评审缺失、重试、断点恢复** | 分母不缩水，失败与 unknown 区分；同 request 不重复计数；成本累加；相同存档重放得相同结论 |

同时做两类外部有效性检查：盲审一组成功/失败轨迹验证自动谓词；在独立场景上检查世界诊断与后续可执行性是否有关，并明确相关不等于因果。报告错判率、适用数和置信区间；VLM 只辅助视觉判断，不能替代可读取的物理真值。

**预期不是所有指标一起变化。** 例如只破坏旧状态时 Expand 应保持不变；否则它与联合保持测的是同一件事。透明的分离比加入一个看似全面的加权总分更有解释力。

## 6. 最小试验与正式试验

1. **接口验收。** 使用已知合法资产检查加载、坐标/尺度、真实动作、状态读取、保存/恢复；脚本或 teleport 可用于调通接线，但记录为工程验证，不能填写物理任务 SR。
2. **g=1 配对 pilot。** 指定杯子先由 Agent 放入抽屉并关闭；扩建新房；扩建后首次回访检查杯子仍在该抽屉，之后取出送入新房。目标卡明确保持到哪一时刻，防止后来重新放回而掩盖丢失。对照至少包括原生增量与合格重生成；外部适配成功后同跑。
3. **验证判定器。** 执行上一节的正/负控制与盲审；失败就修复评测实现，用开发集重验。所有校准样本与正式测试隔离。
4. **冻结正式协议。** 独立 pilot 决定样本量/精度、实际共同任务集、预算、容差和 g；现拟议 g=4，另报 1/2/4/8 曲线。每个新增空间必须承担不可省略的任务作用，早期状态在最后一次扩展后仍被使用。
5. **正式配对运行。** 每个独立世界/任务种子克隆给所有适用方法，方法顺序按硬件/批次分块随机化；Agent 重复种子嵌套在世界内。置信区间以独立世界/任务序列为单位，不能将帧或四次扩展当四个独立世界。

先运行少量 pilot 是工程可行性检查，不预先把任意小样本数称为足够发表。样本量由独立 pilot 的变异和希望分辨的差异/区间宽度确定。最终报告 SR 的配对差值和区间，而不只报告各方法点估计或从多个指标中挑显著项。

## 7. 最少需要保存的证据

| 记录 | 必需内容 |
|---|---|
| 运行身份 | method/generator/adapter/executor/evaluator 版本、独立 seed、任务卡摘要、模型修订与权重哈希 |
| 扩展事件 | 每次请求何时释放、原状态快照、交付物、实际加载状态、映射、连接验证、阶段失败原因 |
| 保持与任务 | 每个受保护谓词和目标的 pass/fail/unknown、适用时刻、物理证据路径、动作轨迹 |
| 账本 | 请求、接纳、加载、探针初始化、执行、成功、确认失败、unknown；重试和未尝试后缀 |
| 资源 | 各阶段实际处理时间、超时、成功延迟、模拟器内存与完整计算/模型成本，明确排除项 |

这些字段是评测输出要求；现有 `manifest` 或 `committed` 状态是否满足要求，需要核验实际运行证据，不能只按名称映射。


审核记录：独立反例审阅提出身份等价与旧区物理变更范围两项缺口，已补入第 2/5 节并经复核确认。此为协议层审核，不代表评测器已实现或外部适配已运行。
