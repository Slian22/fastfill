A. Dataset
We curate MesaTask-CTRC, a dataset explicitly designed to train hierarchical spatial reasoning, derived from the MesaTask-
10k repository (Hao et al., 2025). While the original dataset provides high-quality 3D assets and raw layout JSONs, it lacks
the semantic annotations required for instruction-following tasks. Our pipeline consists of three stages:

A.1. Geometric Relationship Extraction
To construct the ground-truth Hierarchical Scene Graph (HSG), we parse the raw absolute coordinates using geometric
heuristics. Let A and B be two objects with bounding boxes BA , BB . We define relationships as follows:

   • Containment (in): A is inside B if the volume ratio V ol(B)/V ol(A) ≥ 1.5 and the intersection over union on the
     XY-plane IoUxy ≥ 0.9.
   • Support (on): A is on B if the vertical gap |zmin (A) − zmax (B)| < δ (where δ = 1cm) and IoUxy > 0.3.
   • Proximity (near): If no vertical relationship exists, we classify spatial relations (left/right/front/back) based on the
     vector connecting their centroids projected onto the table plane.

A.2. VLM-Augmented Instruction Synthesis
We employ a “Caption-then-Instruct” pipeline using the current state-of-the-art Vision-Language Model (VLM) to bridge
the modality gap:

  1. Multi-View Captioning: We render the scene from four orthographic angles (Front, Top, Left, Right). The VLM
     receives these images along with the textual Scene Graph and generates a dense description D (< 200 words) focusing
     on spatial configurations (e.g., ”A cluttered study desk where a laptop sits centrally on a stand, flanked by a stack of
     books to the right...”).
  2. Instruction Generation: Conditioned on D, we prompt the VLM to act as a user and issue a goal-oriented command
     I (< 30 words). We enforce an ”actionable” constraint: the instruction must imply the arrangement rather than listing
     coordinates (e.g., ”Set up a workstation for coding with reference materials within reach”).

This process yields 9,429 training pairs and 866 benchmark pairs. The benchmark is manually verified to ensure no data
leakage.

B. Implementation Details.
B.1. Model Architecture and Training
We utilize Qwen3-VL-8B (Bai et al., 2025) as our backbone. All experiments are conducted on 640 GB VRAM within a
cluster of 8× GPUs using DeepSpeed ZeRO-2 optimization.
Stage 1: Supervised Fine-Tuning (SFT). We perform full-parameter fine-tuning to align the model with the CTRC format.

  • Optimizer: AdamW with β1 = 0.9, β2 = 0.95.
  • Learning Rate: 1 × 10−5 with Cosine Decay (warmup ratio 0.03).
  • Batch Size: Global batch size of 64.
  • Epochs: 5.

Stage 2: Physically-Aware RL (PADA). We freeze the backbone and train LoRA adapters to inject physical gradients.

  • LoRA Configuration: Rank r = 16, Alpha α = 32, applied to q proj, k proj, v proj, o proj,
    gate proj, up proj, down proj.
  • Algorithm: Group Relative Policy Optimization (GRPO).
  • Group Size (G): 4 samples per prompt.
  • Learning Rate: 5 × 10−4 (constant).

                                                         15
                       PhyScene3D: Physically Consistent Interactive 3D Tabletop Scene Generation

   • Batch Size: Global batch size of 128.
   • Epochs: 1.
   • KL Coefficient (β): 0.04 (initial) with adaptive adjustment.
   • Semantic Anchor Weight (γ): 0.1 (weight of the semantic consistency loss).

Note that in PADA*, we apply a mask when computing the CE loss for anchor samples, supervising only the semantic part.
This is because the BBox and rotation values need to be explored by GRPO and should not be aligned with pseudo-labels
that contain collisions.

C.2. Semantic Fidelity (GPT-Score)
We employ GPT-4o as an external evaluator. The model is provided with the text instruction and the generated JSON
layout (parsed into natural language descriptions of relative positions). It scores the layout on a scale of 1-10 across five
dimensions:

  1. Consistency with Task (CwT): Does the scene serve the function implied by the instruction?
  2. Object Size Reasonableness (OSR): Are objects scaled realistically relative to each other?
  3. Placement Plausibility & Intersections (PPI): Are objects placed logically (e.g., mouse near keyboard) without
     obvious overlapping descriptions?
  4. Layout Coherence & Realism (LCR): Does the global arrangement reflect a human-like workspace?
  5. Object Visibility (OV): Are smaller objects obscured or hidden inside unrelated containers?

The Average GPT Score is the arithmetic mean of these five components.

F. Generative Diversity Analysis
Conventional reinforcement learning is known to cause mode collapse, and conservative layouts with reduced positional
variance are frequently produced. To verify whether PADA preserves generative diversity, the number of distinct asset
types and the spatial standard deviations along the X and Y axes were measured for both IID and OOD scenarios. As
shown in Tables 7 and 8, a noticeable decline in diversity is observed for pure GRPO without semantic anchors, reflected by
smaller positional standard deviations. In contrast, spatial diversity comparable to that of the SFT baseline and MesaTask is
maintained by PADA, which employs semantic anchors refined by TTO together with KL divergence constraints.

I. Failure Cases and Limitations of AABB
The limitations of AABB representations are fully acknowledged, particularly for objects with extreme irregular shapes.
For instance, occupied volumes that are significantly larger than the actual physical extents are assigned to objects with
large cavities or C shaped structures, such as woven baskets with tall handles or over ear headphones. In rare cases, overly
conservative behavior is induced in the PADA engine during optimization, and surrounding objects are pushed farther apart
than necessary, producing locally sparse layouts.
