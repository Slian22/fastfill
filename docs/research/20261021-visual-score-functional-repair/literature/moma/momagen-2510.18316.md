# MoMaGen: Generating Demonstrations under Soft and Hard Constraints for Multi-Step Bimanual Mobile Manipulation
- Authors: Chengshu Li, Mengdi Xu, Arpit Bahety, Hang Yin, Yunfan Jiang, Huang Huang, Josiah Wong, Sujay Garlanka, Cem Gokmen, Ruohan Zhang, Weiyu Liu, Jiajun Wu, Roberto Martin-Martin, Li Fei-Fei. arXiv Oct 2025 (ICLR 2026). https://arxiv.org/abs/2510.18316 (read: arxiv.org/html/2510.18316v2)
- What: MimicGen-style demo generation for mobile manipulation in BEHAVIOR/OmniGibson, cast as constrained optimisation over base, torso, both arms; from N_src = 1 human demo.
- Task family: 4 multi-step bimanual tasks: Pick Cup (navigate to table, lift cup), Tidy Table (cup countertop -> sink, long-range), Put Dishes Away (2 plates countertop -> shelf), Clean Frying Pan (scrub with brush). Success criteria per task not given in text (unverified).
- Robot: Galaxea R1 (ZED 2 head camera, ZED Mini wrist camera); TIAGo cross-embodiment noted ("bulkier arms ... self-collisions"). No base/reach numbers in this paper (see brs-2503.05652.md).
- Base placement: hard constraint "ensuring sampled base poses keep all required end-effector trajectories within reach"; checked by IK (cuRobo). Sampling = "random sampling within a ring-shaped region around the target"; ring radii, sample counts, yaw range not stated.
- Visibility: hard during manipulation ("task-relevant objects must remain in view", head camera "without occlusion"); soft during navigation (cost biasing head camera to target). Metric = "% of frames where the target object is visible during navigation". Table 3 (D0) MoMaGen 1.00 / 0.86 / 0.79 / 0.69 vs SkillMimicGen 1.00 / 0.40 / 0.71 / 0.65. FOV / pixel thresholds not stated.
- Randomisation: D0 objects "within +-15 cm and +-15 deg on the same furniture" (Pick Cup 0.3 m x 0.3 m); D1 "anywhere on the same furniture" (Pick Cup 1.3 m x 0.8 m); D2 = D1 + floor obstacles/distractors.
- Generation success (Table 2, Pick Cup / Tidy Table / Put Dishes Away / Clean Frying Pan): D0 0.86/0.80/0.38/0.51 (avg 63%); D1 0.60/0.64/0.34/0.20; D2 0.47/0.22/0.07/0.16; baselines 0 on D1/D2 ("objects are beyond the reachability of replayed base poses").
- Failure causes: "Base Sampling failures occur when no base pose is found that satisfies reachability and visibility constraints"; sim instabilities 35% of failures; arm-level planning ~40% and base-level ~26% of planner failures on average; "in D2 ... navigation-related failures (base sampling, base IK, and base TrajOpt) increase significantly". Suggested fix: sampling "biasing toward regions with greater free space".
- Relevance: the closest statement of our need: a layout must admit a collision-free base pose near the target from which the target is reachable AND visible; free floor space around receptacles drives base-sampling failure. Ring-sampling + IK is the check pattern to reproduce symbolically (annulus of free cells around the receptacle).
