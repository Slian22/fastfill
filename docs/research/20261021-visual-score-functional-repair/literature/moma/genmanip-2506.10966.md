# GenManip: LLM-driven Simulation for Generalizable Instruction-Following Manipulation
- Authors: Ning Gao, Yilun Chen, Shuai Yang, Xinyi Chen, Yang Tian, Hao Li, Haifeng Huang, Hanqing Wang, Tai Wang, Jiangmiao Pang (Shanghai AI Lab et al.). Jun 2025, CVPR 2025. https://arxiv.org/abs/2506.10966 (HTML v1 read)
- What: tabletop only, "a single Franka Arm on Isaac Sim 4.1.0". GPT-4 builds a task-oriented scene graph (ToSG, ~50 unique objects per scenario); objects topologically sorted by "on"/"in" and placed level by level; "Placements that violate the scene graph constraints are discarded"; "near" uses a threshold "(e.g., 5 centimeters)". Executability ensured "by collecting at least one valid demonstration". Benchmark 200 scenarios (arXiv abstract) vs 250 (CVPR listing).
- Success: up to 9000 physics steps (~150 s at 60 FPS); SR and SPL; final relations inferred from point clouds with named thresholds (XY_DISTANCE_CLOSE_THRESHOLD, MAX_TO_BE_TOUCHING_DISTANCE, ANGLE_THRESHOLD; values not in text, unverified).
- Numbers: best modular CoPA+GPT-4.5 SR 23.00 / SPL 5.26 (Table 2); by number of goals SR 32.28 / 18.69 / 0.00 for 1/2/3 goals; distractors 0/1/2 -> 20.27 / 18.60 / 18.00; oracle grasp 50.0-65.0 SR. GR-1: 33.0% (100 eps) -> 95.0% (1k) single task; 0.0% on unseen instructions + objects.
- Failure causes: grounding (wrong SoM masks), ungraspable grasp proposals, grasp collisions with neighbours (e.g. blue can interfering with a nearby bottle), wrong anchor object, unexecutable motion plans. No reachability/occlusion attributed to layout.
- Relevance: not mobile; useful only as a precedent for "born-false goal relation + at-least-one-demo executability certificate" and for showing neighbour clutter causes grasp collisions.
- Tags: scene-gen-for-robots, data-generation, VLA-policy, 3D-memory/scene-graph, long-horizon
