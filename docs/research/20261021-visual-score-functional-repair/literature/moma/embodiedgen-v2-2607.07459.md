# EmbodiedGen V2: An Agentic, Simulation-Ready 3D World Engine for Embodied AI
- Authors: Xinjie Wang, Liu Liu, Taojun Ding, Andrew Choi, Chaodong Huang, Mengao Zhao, Ziang Li, Jackson Jiang, Chunlei Yu, Shengxiang Liu, Wei Xu, Zhizhong Su. Jul 2026 (v3 Aug 2026). https://arxiv.org/abs/2607.07459 (HTML read)
- What: task-driven worlds (Sec 2.4): LLM splits task into ROBOT/BACKGROUND/CONTEXT/TARGETS/DISTRACTORS, builds a shallow scene graph (edges ON, INSIDE, FLOOR, IN), places breadth-first (siblings sorted by footprint), settles in SAPIEN. Multi-room scenes (Sec 2.5): VLM picks room scope + complexity (Minimalist/Simple/Medium/Detail); constrained solver in three passes (skeleton furniture -> mid-scale on supports -> tabletop clutter).
- Layout constraints: support predicate = child footprint on parent support region (must be 1); footprint IoU with placed siblings must be 0; gravity settling. "Manipulated objects must additionally lie within the robot's reachable, forward-facing interaction region" (region size not given). "The solver resamples infeasible samples under room-connectivity and navigable-opening constraints" (no width/radius/grid given).
- Robot eval: asset grasp test with Franka Panda in SAPIEN, 4 top-down grasp-and-lift trials per asset, "collision success" 98.6%; grasp discarded if slip "exceeds 55 cm or 30°" (as printed; likely typo, unverified). Online RL in generated scenes: sim success 9.7% -> 79.8% (Table 5); real world 21.7% -> 75.0% over 12 scenes / 240 trials, dynamics failures 66.7% -> 18.3%. Real-robot embodiment not stated in text read (deferred to Choi et al. 2026, unverified). Mobile manipulation claimed as supported, not quantified.
- World acceptance: 83.3% of 150 task-driven worlds usable without manual edits (criteria: task semantics, spatial relations, scale, stability, robot executability). Failures "mainly arise from object-scale mismatch, local geometry defects, or imperfect initial spatial placement"; Fig. 11 lists task-constraint violation, scale mismatch, unstable placement; no per-cause counts.
- Relevance: the downstream engine family we feed; it treats reachability and navigable openings as hard resampling constraints but publishes no thresholds, so our checks must define them ourselves.
