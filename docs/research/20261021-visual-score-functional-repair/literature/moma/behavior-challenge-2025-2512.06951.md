# BEHAVIOR Challenge 2025 (NeurIPS 2025) + 1st-place report "Task adaptation of Vision-Language-Action model"
- Sources: official pages https://behavior.stanford.edu/challenge/archive/2025/index.html , .../call_for_participation.html , .../evaluation.html ; winner: Ilia Larchenko, Gleb Zarin, Akash Karnatak, arXiv Dec 2025, https://arxiv.org/abs/2512.06951 ; 2nd place Openpi Comet https://arxiv.org/abs/2512.10071 (numbers from search snippet only, unverified).
- What: 50 full-length BEHAVIOR-1K household tasks in house-scale OmniGibson scenes ("50 high-fidelity, fully interactive scenes populated with around 10,000 objects"); 10,000 teleop demos (200/task, 1200+ h).
- Robot: "Galaxea's R1 Pro robot, a wheeled humanoid"; action = "absolute joint angles for all the robot joints (23-dim)". Specs not on the pages.
- Success: BDDL goal conditions; "Partial successes = (Number of goal BDDL predicates satisfied at episode end) / (Total number of goal predicates)"; timeout "2 * average human task completion time within the demo dataset"; 10 eval instances/task (+10 held-out final); only initial object states and robot pose randomised. Secondary: sim time, base distance, hand displacement (normalised vs human).
- Results: winner q-score 0.2605 public / 0.2599 private; binary success 0.1120 / 0.1240. 2nd place q 0.2514, 22/50 tasks completed (unverified, snippet).
- Failure causes (winner, 15 of 50 tasks labelled): dexterity "around one-third of failures"; other categories without counts: order, confusion, robot fell, reasoning, search, navigation, reachability, catastrophic error, whole-body coordination, robot stuck (base contact blocks motion), head camera visibility ("The head camera does not cover the floor in front of the robot or shelves above the head").
- Relevance: visibility failures are tied to height: floor right in front of the robot and shelves above head height are blind spots for an R1 Pro head camera; reachability and base-stuck are named failure classes. Scene layouts are fixed in this challenge (only object/robot poses randomised), so layout is not studied as a variable.
