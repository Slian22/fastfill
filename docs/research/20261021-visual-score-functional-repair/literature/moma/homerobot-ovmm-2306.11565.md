# HomeRobot: Open-Vocabulary Mobile Manipulation
- Authors: Sriram Yenamandra, Arun Ramachandran, Karmesh Yadav, Austin Wang, Mukul Khanna, Theophile Gervet, Tsung-Yen Yang, Vidhi Jain, Alexander William Clegg, John Turner, Zsolt Kira, Manolis Savva, Angel Chang, Devendra Singh Chaplot, Dhruv Batra, Roozbeh Mottaghi, Yonatan Bisk, Chris Paxton. arXiv 20 Jun 2023 (v2 10 Jan 2024; NeurIPS 2023 challenge benchmark). https://arxiv.org/abs/2306.11565 ; code configs: github.com/facebookresearch/home-robot (projects/habitat_ovmm) + pinned habitat-lab commit b727ca9 (habitat/config/benchmark/ovmm/ovmm.yaml, datasets/rearrange/viewpoints.py, navmesh_utils.py, configs/ovmm_val.yaml)
- What: OVMM = "Move (object) from the (start_receptacle) to the (goal_receptacle)"; sim on HSSD (60 scenes: 38 train / 12 val / 10 test; 2,535 objects, 129 categories, 21 receptacle categories) + real Stretch in one apartment.
- Robot: Hello Robot Stretch with DexWrist (6 DoF manipulation). Sim config: agent radius 0.3, height 1.41 (ovmm.yaml); episode-generation agent radius 0.25, height 1.41, max_climb 0.01, camera height 1.31 m, hfov 42, tilt -30 deg (ovmm_val.yaml). Arm joint ranges in config comment: 4 telescoping joints 0-0.13 each (0.52 m total extension) and lift 0-1.1. Nav planner treats robot as a cylinder; the rotation-centre offset of Stretch "is not modeled". Base step 0.25 m / turn 30 deg; 5 cm FMM map cells.
- Success (sim): FindObj = within 0.1 m of a target viewpoint with >= 0.1% pixels of the object (min_object_coverage_iou 1e-3); Pick = gripper enabled while object visible and end-effector within 0.8 m (grasp_thresh_dist 0.8, oracle snap); FindRec same as FindObj for goal receptacle; Place = object stays in contact with goal receptacle 50 contiguous steps with low velocity (angular 5e-2, linear 5e-3) and no scene collision; limit 1,250 steps. Real: within 1 m and visible; 300 timesteps. Place spawn heading error <= 15 deg; nav spawn >= 3 m from target.
- Layout requirements in episode generation: largest indoor navigable island only (active island, indoor ratio >= 0.85); receptacles "too small for object placement" filtered (threshold not given in text, unverified); objects placed only where "navigable" and "reachable, meaning its arm can make it to these locations"; object count per scene 1.5-2x total receptacle area in m2 (paraphrased by fetch, exact wording unverified); object must snap to the active island within nav_to_min_distance 1.5 m (Euclidean, code notes it can be separated by an obstacle).
- Viewpoint rule (code, viewpoints.py): candidate grid 0.15 m over object AABB + 1.0 m; keep if snapped to active island (<= 0.075 m snap), OBB distance <= 1.0 m, navigable floor below, and summed pixel coverage over 3 head tilts >= 0.001; else typed failure (not_on_active_island / too_far / down_unnavigable / low_visibility). Paper text says viewpoints within 1.5 m (code uses 1.0 m).
- Robot-footprint check (navmesh_utils.is_navigable_given_robot_navmesh): robot modelled as 3 circles at offsets 0, +0.25, -0.25 m along its axis, tested at 4 rotations every 0.3 m along the path.
- Results: sim best (RL, GT perception) FindObj 66.6 / Pick 61.1 / FindRec 50.9 / overall 14.8 / partial 48.3 %; with DETIC near 0 overall. Real (20 eps): heuristic 15% / RL 20% overall. Failure causes qualitative: perception (DETIC); "Both RL and heuristic skills struggled to navigate tightly constrained multi-room environments"; no per-cause percentages.
- Relevance: the viewpoint generator is a ready-made spec for our "see each task object" check: free base cell within 1.0 m of the object OBB on the main island + visibility >= 0.1% pixels from 1.31 m camera. Agent radius 0.25-0.3 m (vs our 0.2 m).
