# MoTo: A Zero-shot Plug-in Interaction-aware Navigation for General Mobile Manipulation
- Authors: Zhenyu Wu, Angyuan Ma, Xiuwei Xu, Hang Yin, Yinan Liang, Ziwei Wang, Jiwen Lu, Haibin Yan. CoRL 2025 (PMLR 305). https://arxiv.org/abs/2509.01658
- What: picks a docking (base) pose for any fixed-base manipulation model: VLM finds target keypoint and arm keypoint, then optimises base+arm motion to bring them together. Costs: collision (robot surface points inside safety margin eps0 of scene point cloud; value not given), smoothness, arm margin (arm radius kept near midpoint of r_min/r_max; values not given). Dual Annealing, Pinocchio IK. Visibility is not a cost; full observability assumed.
- Robot: Hello Robot (Stretch) in OVMM sim; real: HEXMOVE base + two PiPER arms.
- OVMM val (Table 1, overall SR): Home-Robot RL 14.80%, UniTeam 17.96%, Home-Robot w/ MoTo 18.32%, OpenVLA w/ MoTo 20.64%. Abstract "+2.68%" not reproducible from table; real-world "+16.67%" only in figure.
- Failure causes (real): base-trajectory smoothing (protection stop), SLAM localisation (robot far from target), optimiser loops, varying stop poses hurting fixed-base policy viewpoint generalisation. Limitations: no whole-body door opening, needs full observability.
- Relevance: base pose = "arm keypoint within [r_min, r_max] of target + collision-free"; stop-pose variability changes the policy's viewpoint -> a layout should leave a reasonably large free region (not a single pose) in front of each target.
