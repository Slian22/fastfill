# ProcTHOR: Large-Scale Embodied AI Using Procedural Generation
- Authors: Matt Deitke, Eli VanderBilt, Alvaro Herrasti, Luca Weihs, Jordi Salvador, Kiana Ehsani, Winson Han, Eric Kolve, Ali Farhadi, Aniruddha Kembhavi, Roozbeh Mottaghi. arXiv 14 Jun 2022 (NeurIPS 2022 venue unverified from page). https://arxiv.org/abs/2206.06994 (read via ar5iv incl. appendix)
- What: procedural houses in AI2-THOR: room spec (16 specs, 1-10 rooms) -> floorplan (min 2 m, ~3 m per room, scale 1.6-2.2) -> doors/openings -> materials -> ceiling 2.5-7 m -> lights -> floor / wall / surface objects. ProcTHOR-10K (10,000 train + 1,000 val + 1,000 test), 1,633 assets / 108 types, 18 semantic asset groups.
- Placement clearances (Sec. B.8.3-B.8.4): middle-of-room objects get 0.35 m margin on each side; edge/corner objects get 0.5 m margin only in front (backs to wall, flush sides allowed); paintings above edge objects only if those are < 1.15 m tall; surface objects 5 pose attempts, <= 3 of a type per receptacle. Door open directions and SAG mesh clipping resolved by rejection sampling.
- Navigability validation (Sec. B.11): agent must teleport into the house; BFS over a 0.25 m x 0.25 m grid from the agent; every room must contain >= 5 reachable grid positions, else resample. Agent radius not given (unverified). No object-reachability or opening-clearance check found in the text.
- Tasks/agents: ObjectNav with LoCoBot (0.25 m steps, 30 deg turns; success = Done with target within 1 m and visible; 500 steps); ArmPointNav with ManipulaTHOR (200-step episodes, 45 deg rotation; zero-shot PickUp success 37.9% vs 29.2% iTHOR baseline).
- Scale ablation zero-shot ObjectNav SR (10 -> 10,000 houses): RoboTHOR 8.53% -> 44.5%, ArchitecTHOR 11.3% -> 27.0%.
- Relevance: closest precedent to our downstream check (same 0.25 m grid, BFS from a start pose, per-room reachability); its 0.35 m / 0.5 m front margins are a cheap symbolic proxy for base-placement space. Weakness: ">= 5 reachable cells per room" does not guarantee reachability of each object.
