# FATE: Closed-Loop Feasibility-Aware Task Generation with Active Repair for Physically Grounded Robotic Curricula
- Authors: Bingchuan Wei, Bingqi Huang, Jingheng Ma + 2 others (5 total). arXiv 2603.01505 v1, 2 Mar 2026. https://arxiv.org/abs/2603.01505
- What: LLM task+scene generator (Objaverse + PartNet-Mobility assets; household-style tasks such as microwave heating, opening a sliding window) wrapped in audit-and-repair loops. Robot: RidgebackFranka (7-DoF arm on holonomic base) in Isaac Sim; BIT*/MPC navigation, SAC manipulation.
- Static audit (Ante-Auditor) axes: affordance matching, geometric reachability, physical plausibility (interpenetration, unstable placement), morphological compatibility (scale fit). No numeric thresholds given. Execution audit: simulation oracle rollouts; "Dynamic Divergence" when the desired state change is not produced within the horizon.
- Repair ops: static SWAP_ASSET, SPAWN_ASSET, REMOVE_ASSET, SET_JOINT, TRANSFORM_POSE, RESCALE; dynamic INJECT_REWARD, SET_RL_HORIZON, REPLAN_PATH, ADJUST_GRASP, TUNE_IMPEDANCE, SKIP_SUBSTEP, RESET_ROBOT_JOINT.
- Results (static-valid / execution-valid / final task yield): Vanilla 41.5/30.4/12.6%; GenSim-V2 58.2/51.2/29.8%; FATE-Static 93.8/69.7/65.4%; FATE full 97.5/94.5/92.1%. Repairs: Ante 201/215 (93.5%), Primitive 39/42 (92.9%), RL 58/76 (76.3%), total 298/333 (89.5%). Auditor F1: semantic 0.95, geometric 0.86, dynamic 0.83. For geometry-sensitive tasks "the primary failure mode is geometric incompatibility" (Open Sliding Window: static 20.6%, dynamic 41.8%, full ~88%).
- Relevance: only MoMa-embodied example found of generate -> audit -> repair for executability; shows open-loop LLM generation yields only 12.6% executable tasks; but checks are unquantified and the repair edits poses/assets per task, not a room layout under a fixed furniture list.
