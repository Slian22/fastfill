# Robot Placement based on Reachability Inversion
- Authors: Nikolaus Vahrenkamp, Tamim Asfour, Ruediger Dillmann (KIT). ICRA 2013 (venue from search results; the PDF text does not name it). https://h2t.iar.kit.edu/pdf/Vahrenkamp2013.pdf (full text read via pdftotext)
- What: precompute a 6D voxelised reachability map of the arm (voxels store reachability/quality, e.g. manipulability), invert it into an Inverse Reachability Distribution (IRD); cutting the IRD with the floor plane at a grasp pose gives the Oriented Reachability Map ORM over (x, y, gamma) in SE(2) = candidate base poses with a quality index.
- Base pose selection: take argmax ORM cells or sample proportional to ORM; for each sample solve arm IK (Jacobian pseudoinverse) then check self- and environment collision; repeat until timeout (Algorithm 1). Trajectories (door/drawer opening): ORM_tr(x,y,gamma) = min_i ORM_i, i.e. a base pose must reach every waypoint.
- Robot: ARMAR-III (43-DoF model; 13-DoF task = 3 base + 10 hip/arm), Simox, 100 queries averaged. Voxel resolution not found in the text (unverified).
- Numbers (Table I, random bottle on table): full ORM query 732.3 ms (726.9 ms ORM setup), lazy ORM 7.0 ms (fixed target 4.4 ms); "less than 10 ms" for the complete 13-DoF IK incl. placement and collision checks. Door opening (Table II): full ORM 1161 / 1158 / 1209 ms (dishwasher / drawer / fridge, ~1.2 s setup); lazy 33 / 10 / 7 ms; 1.6-5.7 base poses sampled per successful query; 4.1-21.6 arm IK calls.
- Follow-ups (exist, not read in detail): Reuleaux (Makhal & Goins, arXiv 1710.01328, open-source IRM base placement; no numbers in abstract); RM4D (arXiv 2410.06968) notes the inversion step is "cumbersome".
- Relevance: the standard way to answer "does a free base pose exist within arm reach of this target": intersect the target's ORM footprint with the free-space grid. For opening tasks use the min over the opening trajectory, so the base region shrinks for doors/drawers.
