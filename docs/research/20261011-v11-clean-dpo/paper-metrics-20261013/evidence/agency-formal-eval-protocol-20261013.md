2. **主输出 final/raw，修复另列。** OOR 对全部1,009按原冻结二维面积比计算，逐房间等权求均值；同时保存 repaired 列但不切换主列。三阶段历史 OOR 可留作辅助描述，不要求本轮视觉评价扩展到 SFT/DPO1。当前六层全部完整输出，OOR 分母应为各层 N；若重验产生差异，先核查输入身份并披露，不静默改变分母。资产不可渲染不影响已可计算的盒级 OOR。

3. **渲染资格与真实资产。** 基于参考资产清单冻结资格：GT/final 同 mesh 身份、材质、房间环境与坐标约定；GT 按参考尺寸，final 按预测 size/pos/yaw。缺 mesh、缺对象或错误单位/轴序逐条记账，不用代理盒、不删难物体、不换容易资产凑 FID。保留预测尺寸意味着这是“参考资产身份辅助的联合尺寸/布局诊断”。覆盖为 GT size 是另一个输出变换，只能另立敏感性，不能偷偷用于主表。相机由房间边界固定，不随预测包围盒/质量调整；光照、背景、分辨率、特征预处理全部冻结。图像丑、碰撞、越界但技术上成功的渲染必须保留；资产/渲染失败须有可审计技术原因。

4. **FID 用全量尝试后的同 ID 条件子集。** 每层记 R_h 为原 N_h 请求；定义 C_h={i∈R_h：GT 和 final/raw 的规定斜视图都成功且资产合同满足}。只在 C_h 上，以同 ID、等图数的 GT 对 final/raw 计算标准 FID；不用 SFT/DPO1 的失败进一步缩小 C_h。每场景一张固定斜视进入 FID，另一个视角不增大 FID 样本数。表中必须列 N_h、资产资格数、GT成功数、final成功数、|C_h|及|C_h|/N_h，注明 conditional。参考是本地真实资产的 GT 渲染，不是照片或论文参考图。n<2 标 unavailable；小样本值只作描述，不以少量图的数值排序宣称模型优胜。六层总体 FID 必须对各 C_h 合并图像重算，不能平均六个 FID；扩展1375总体另算另标。修复后若另测，可有自己的 GT/repaired 子集；要量化修复差异则另在 GT/raw/repaired 三者共同成功集重算两项，不能直接相减不同子集的 FID。

5. **GPT 从完整六层预抽300，不从可渲染成功者抽。** 各层按 v1 已定 hash/seed/序列化规则取前50，运行前保存完整排序及所选ID；如已有清单，原样冻结，不重抽。缺资产、渲染失败、API失败一律不补位，不随机补好案例；每层选中分母始终50。评审只测 final/raw，提交原请求文字及同一候选的固定顶视+斜视，不提供 GT 图、指标、阶段名或获胜暗示。若样本缺任何规定视角则记渲染未完成，不临时换成另一种评审输入。

6. **GPT 三维单独报、失败单独报。** functionality/layout/aesthetics 分别0–10，冻结提示、Krill `gpt-6.1-sol` 请求/实际响应模型标识、参数及时间。标签写“GPT-6.1-sol 三维视觉评分”，不能写成 GPT-4o 或人工UR。均分分母为该层实际有效评审数 J_h；同时列 J_h/50 和失败原因，不把缺资产/API错误填0，不把三项分数当三倍样本。统计区间采用预先固定的层内整 `(source,group)` 重采样2,000次/seed42的95%百分位区间；标探索性、条件于有效评分和固定评审器，组数不足2不出区间，组数很少明确不稳定。该区间不覆盖供应商模型变化、人工一致性或失败选择偏差。不另做显著性筛选。仅在六层均50条完整评分时，才可按 N_h/1009 加权给出六层总体均分估计；简单平均300条是六层等权结果。存在失败时不把加权成功者均分称无偏总体结果。

7. **有界执行。** final/raw最多300次初始 GPT 调用；仅技术/格式失败最多一次同参重试，总尝试至多600，成功评分不重试。沿用父代理冻结的费用/token上限，到限保留 partial，不加样。最低图像计划：六层 GT+final 斜视最多2,018张，加选中final顶视最多300张，共2,318张；若先渲染两来源1375的全部斜视则最多2,750+300=3,050张。这是唯一图像目标数，不含有日志的故障重试；不要求为了FID把GPT扩大为全量。修复后视觉/API如另测，另列范围与预算，不挤占或替换 raw 主测。

8. **测试结果只用于报告。** 在读取新FID/GPT分数前冻结本节、IDs、资产映射、尺寸策略、相机、提示、失败规则和实现哈希。只在独立 dev/smoke 样本调接口和渲染。新test不能用于调阈值、换checkpoint、挑seed/角度/提示或再训。技术修复依据报错/合同核验，记录版本，对所有受影响请求同规则处理并保留旧记录；不能把低评分当修复依据。已有OOR与部分test已查看，因此整体仍是诊断性研究。

9. **交付表与状态。** 每层主表至少包含 `N / OOR raw / OOR repaired / asset eligible / GT rendered / final rendered / FID common n / FID / GPT selected=50 / GPT valid / 三维均值及CI / human UR=not measured`。另附逐ID原因ledger、渲染/资产/模型/评分配置哈希和原始API响应。OOR全1,009=几何覆盖完成；全部请求均尝试或记录明确资格失败=执行完成；FID/GPT只完成子集=视觉覆盖部分完成。人工UR没有真实5人多数票则保持未测。最终固定表述：**同指标/同评分维度的条件诊断，非论文匹配基准，非阶段改进证明。**

## 2. 抽样与可渲染资格

在渲染与调用前生成完整 1,009 行 manifest：原始行号、uid、source、group、room_type、三阶段输出哈希、GT 资产引用。以协议 ID `formal-diagnostic-20261013-v1` 和 seed `42` 为盐，对每层每条 `(source, room_type, uid, 原始行号)` 的固定序列化内容做 SHA256 排序，取前 50 条；公布序列化规则、完整排序与最终 ID。这是结果无关的固定伪随机房间样本。各阶段复用同一 300 条；不是每阶段各挑 50，也不是每组挑一条。保留原始重复请求并标注；组内相关在分析中处理。

抽样来自完整六层，**不因缺资产、生成/渲染/API 失败补抽**。先做只依赖参考数据的资产清单审核，冻结“可渲染资格”：全部要求对象有真实 mesh/材质，单位/轴序及 bbox 可验证，参考场景可建立。缺目录、坏 bbox、缺对象均写原因，不得静默删对象、补代理盒或检索一个更容易的资产。可单独生成盒子示意图，但不纳入真实资产 FID/GPT。修正资产元数据应依据 mesh/原始数据，在比较图和评分前统一冻结；若只能事后修正，另立版本、全方法统一重跑并保留旧结果。

## 3. OOR：保留全量、两种输出、原始分母

OOR 跨房间用等房间均值，不能改为所有房间面积之和作分母。若输出文件重验后出现失败，保留在请求计数中，OOR 记 unavailable；失败不能计 0。主六层目前 complete=N；未来若不等，新增共同完成 ID 的配对敏感性及其分母，不能悄悄只展示成功者。

## 4. 真实资产、尺寸和 FID

**主渲染合同：共享参考资产身份，保留各模型预测 size/pos/yaw。** 同一请求的各阶段与 GT 使用相同 mesh/材质映射和房间环境。模型物体按预测尺寸映射 mesh；参考按参考尺寸。轴序、缩放、坐标/支撑变换必须统一，不能根据图像好坏改姿态或修碰撞。明确命名“GT 资产身份辅助的联合尺寸/布局诊断”；它不评价资产检索，也不是论文给定尺寸布局任务。非均匀缩放导致的形变属于该合同的实际输出，不能隐藏。

把预测 size 覆盖为 GT size 会改变输出，只能预先声明为另一个受控尺寸敏感性，不能替代主结果或称论文复现；即便覆盖，模型原提示仍未变成论文提示。GT 与模型共用资产会影响视觉距离，必须披露这一参考辅助条件。

相机以**参考房间边界**固定：一个顶视、一个固定方位斜视；不根据预测物体包围盒重新居中/放大。统一墙体裁切、光照、背景、分辨率（本协议建议 512×512）、材质和渲染引擎。在独立 dev/smoke 场景调通后冻结具体变换矩阵/生成规则。越界导致出镜仍是结果；不能逐图挑角度。

FID 使用每层全量资格场景，不缩减为 50。主 FID 只用固定斜视每场景一张图；顶视留给 GPT，避免把同一房间两视角当两倍独立样本。参考分布为**同 ID 的本地真实资产 GT 渲染**，不是实拍照片、不是论文的未知参考图，更不是预测图或训练集图。保存每张参考/输出图及哈希。

对每层定义 C_h = GT 与三阶段 raw 斜视均成功的共同 ID 交集，在 C_h 上每个模型与同一 GT 参考计算 FID，严格相等图数；另报 N_h、参考可用数、各阶段成功数和 |C_h|。此为“共同可渲染子集上的 FID”，不能代表全部请求。严禁用黑图、重复图或较容易替补场景填失败。即使缺失来源是系统故障，也保留审计。少于 2 个共同场景不算 FID；其他小样本可出值但不得作显著胜负结论。

锁定同一个现有 FID 实现、依赖版本/权重哈希、2048 维 Inception 特征及预处理。没有标准权重时记该项未完成，不改用 CLIP 距离后仍称 FID。各层 FID 不做算术平均冒充总体 FID；需要总体时，用各层 C_h 的合并图像另算，并披露组成。最小方案只报告描述性 FID、样本数和覆盖，不追加事后挑选的显著性检验。等样本量不能消除 FID 的有限样本、模型相关偏差：[Chong & Forsyth, CVPR 2020](https://arxiv.org/abs/1911.07023)。

## 5. Krill `gpt-6.1-sol`：三维评分而非 GPT-4o 复现

只用用户授权的既有接口。父代理在正式调用前验证其支持图像输入，记录请求 model 字符串、响应实际 model/deployment ID、服务版本/日期、参数、usage 和 request ID；无法核实底层快照则写“供应商别名、底层版本未证实”，不得宣称模型等价或更准确。文本-only 不可冒充视觉评分。

每条给原始请求文字（已有物体/偏好/约束）与两张候选渲染，不给 GT 布局/参考图、阶段名、OOR/FID、先前分数或获胜暗示。使用已整理的论文表9三维含义和 0–10 尺度，冻结提示；为结构化返回增加格式要求可以，但必须保存差异，不称逐字协议复现。三项分别为 functionality/layout/aesthetics，不取最大值、不把三项称独立重复实验。

请求顺序按固定 hash 打乱，stage 用盲码，单场景单方法评审；支持时 temperature=0 并记录，仍不承诺确定性。不因低分重试。超时、限流、5xx、空结果/字段缺失/越界评分最多一次同参重试，保留两次原始响应并取首个有效评分；仍无效则记 API/解析失败。若端点或模型版本变更，停止当前批次、记 partial，不静默混评。

每层/阶段报告选中 **50**、生成成功、资产合格、渲染成功、有效评审数和各失败原因。GPT 均分仅对有有效评分者，明确条件分母；API/缺资产不计模型 0 分。阶段差主分析只用三阶段均有效的共同 ID，单独列该分母和 `(source,group)` 数；不宣称这个成功子集代表完整 N_h。50 条最终有效不足仍报实际数，不补抽、不延长直到显著。

分别报告三个维度均值和预先固定的相邻阶段配对差。可用层内整 `(source,group)` 重采样 2,000 次、seed42 的百分位 95% 区间，标“探索性、单比较、固定模型/评审器条件下”，不足两组不出区间，少数组明确不稳定。不作跨六层×三维×两对比的整体显著性结论；最小交付可只给均值/配对差并明确未估计区间。主表不汇总一个赢家分；等额50的混合均值不是1,009总体房间均值。除非每层完整观测，否则不要仅靠 N_h 权重声称纠正了失败选择。

## 6. UR 与防止新测试调参

UR 填 `not measured / 未进行人工评审`。可直接复用预抽300条建立将来盲评队列，只有每场景5名真实评审、至少3票认可物理与语义有效，才出人工 UR；记录逐人票、失访和场景分母。GPT票、自动验收、五次模型调用均不可替代。真实人评在本最小执行包之外，不影响其他三项诊断完成状态。

正式读取新 FID/GPT 前冻结本协议、输入清单、参数、失败/重试规则、分析表和预算。只允许用独立 dev/smoke 样本验证接口、相机和解析。新 test 分数不得用于换 checkpoint、尺寸阈值、后处理、资产、相机、提示、抽样 seed 或再训。技术故障修复须记录原因与受影响范围，同方法同规则处理；不能把质量差叫技术失败。将来的方法改动用 dev，并另设未见 holdout；本次 test 此后明确为已查看。
