# Reality Checker：未知尺寸比较的最小验收设计（2026-10-13）

**推荐：以未知尺寸联合预测为唯一主任务，主表最多两个可识别系统：fresh-base V1.1 joint，与 train-only SizePrior → matched OptiScene-style placement pipeline。known-size/GT-size仅独立信息更充分参考。不要把直接改为size输出的OptiScene另起名字当作第二方法。**

对象明确为当前 **V1.1：直接JSON SFT→DPO1→DPO2**，不是v2结构化模型。本文仅复核现有 `docs/research/20261011-v11-clean-dpo/paper-alignment-20261013.md` 并设计验收；未重扫代码/数据，未训练、提交任务、调用付费API或改正式文档。统计估计/样本量由Statistician补充，论文方法命名由ResearchSynthesist整合，合同和checkpoint实现由ModelQA核查；本文负责可识别对照与停止条件。

## 1. 主合同与最小矩阵

主请求：房间边界/允许的固定障碍及其合法尺寸、对象类别/描述、用户约束；**可移动对象真实尺寸与目标位置/朝向不可见**。联合系统输出size/pos/yaw/on；pipeline输出估计size加摆放器pos/yaw，经过无GT访问的确定性格式适配进入同一场景评分器。支持关系等扩展字段的适配规则预先定义；不能为基线偷偷删掉困难对象、约束或房型。

| 单元 | 训练与输入 | 可回答的问题 | 必需程度/成本 |
|---|---|---|---|
| **U-J：V1.1 joint** | 可核验公共Qwen3-8B revision fresh start；修正ID/顺序；共同多源训练场景；直接JSON SFT→DPO1→DPO2 | 联合尺寸/布局系统在新unknown-size合同上的结果 | **主表必需：一条新训练链**；保留SFT、DPO1、DPO2作为阶段消融，不另练三套完整模型 |
| **U-P：SizePrior + OptiScene-style matched placement** | 同一fresh base、共同训练场景和合法原始信息；训练集尺寸先验给size，摆放器输出pos/yaw；固定相当的资源/调参预算 | 联合预测 vs 显式先尺寸后布局的**系统分解比较** | **主表唯一外部适配基线：一条新摆放器训练链**；先验统计不需额外神经网络训练 |
| **K-P oracle（可选诊断）** | 若摆放器支持，给同一个U-P摆放器GT尺寸，独立标注输入信息变化 | 尺寸估计瓶颈与信息增益的诊断 | 无新增权重训练；额外推理。它不是保证更高分的数学上界，也不是原论文结果 |
| **K-original reference（可选）** | 可核验原作者known-size权重/公开方法重实现，给GT尺寸 | 原方法在其信息条件下的参考 | 不进入主胜负表。原论文严格复现、官方676身份、完整视觉指标不是当前主线前置条件；不默认新开此训练 |
| **Legacy V1.1** | 现有warm-start模型和归档结果 | 历史可运行性、阶段诊断 | 保留现有结果；不得充当same-fresh-base因果对照，旧输入结果不得当新合同结果 |

两个主系统只在同一unknown-size请求上比较；K列与U列不计算“胜过原论文”差值。共同known-size matched不是默认再开两臂的新任务。若U-P无法得到足够忠实、有效的实现，先交付U-J阶段实验并缩小主张，不能造一个同算法改名基线补数。

**不做full factorial**：不默认加入reasoning有/无 × 两种数据量 × 三阶段 × known/unknown-size × 多种基座。只保留已训练链的阶段快照。额外reasoning、数据规模或等预算SFT续训对照仅在相应主张确实需要时再选一个。阶段差值回答“这一步训练后的变化”，不能单凭它证明DPO比同算力继续SFT更优；本轮也不默认声称多源数据扩展具有因果收益。

## 2. 对SizeEstimator + OptiScene pipeline的独立判断

**推荐，优于将OptiScene直接改为size输出后作为不同算法。** 其可观察差别是因子分解：`request → size estimates → positions/yaws`，对照joint的联合生成。它保留known-size摆放器接口，适合检验尺寸误差传播及联合适应；它是适配系统，**绝不是论文复现**。

最便宜且可审查的第一版估计器是训练集 `(category, room_type)` 条件尺寸统计，例如训练集对数尺寸中位数；稀疏组按预先固定规则退回category/global prior。阈值/回退规则由train/dev确定后冻结。原始输入有描述时，先验不利用全部描述是基线能力限制，须披露，不等于初始信息获益。不要立即升级独立SizePredictor；先验误差在dev上明显主导系统失败时才考虑替换，避免堆模型。

- **共同数据matched placement**：与U-J用同一fresh基础模型revision、可用训练场景、分组划分、合法请求、测试实例及资源上限。可识别的干预是joint vs 分阶段系统；即使上述条件相同，也不能把差值解释成某个DPO损失或单一组件的因果效果。
- **原作者数据训练的transfer reference**：即使用相同架构，也改变训练数据、监督与预算，只是迁移适配参考。它可以先验证接口、估计成本，但不能替代matched主对照或支撑“joint算法更好”。没有可验证作者权重时明确写“公开方法重实现”，而不是作者模型。
- **先验严格train-only**：test不能拟合类别统计、挑回退阈值、训练估计器或查目标资产真实bbox；也不能利用目标派生ID还原尺寸。模型训练时使用估计尺寸/噪声输入，应由按场景族分组的OOF估计得到；每折不能看到本折或跨源重复场景的尺寸。dev/test只用全部train拟合的估计器。若未来改神经SizePredictor，保持此边界。
- **训练分布需认真对齐**：只在GT尺寸上训练摆放器、测试突然给估计尺寸，是合法但较弱的transfer baseline，应明确记录该分布变化。推荐matched摆放器有预先固定的OOF估计尺寸暴露；不能为压低基线刻意保留该落差。
- **不能盲目复用GT布局/偏好标签**：OOF估计尺寸改变后，原chosen布局可能碰撞或越界；用实际输入尺寸复核SFT/偏好监督的可满足性。固定train-only的重建/过滤政策及预算，记录两臂准入差异。known-size摆放器不能改变size，因此不能使用仅靠“输出尺寸损坏”构造、而其输出根本不含size的DPO负例。它们应换成可控位置/朝向错误或明确不适用；不能称为逐对相同偏好实验。
- **命名边界**：若没有原human DPO1或reasoning监督，就不能暗示原human-aligned/reasoning方法被完整复现。可用 `SizePrior + OptiScene-style placement (programmatic preferences; no reasoning)` 等明确名称。不要为保住“OptiScene”名字临时增加人工标注/LLM理由生成，扩大本轮范围。

若两臂都用直接JSON与相同程序DPO流程，其**优化算法可能相同**；本比较仍有效的差别在“独立尺寸先验+条件摆放”与“联合尺寸布局生成”。合理论文主张是未知尺寸任务、共同多源协议及系统设计，不能宣称发明了新SFT/DPO算法。

## 3. 五个最关键失败假设与验收gate

| 失败假设 | 必须保存的可验证gate | 未通过时的结论/动作 |
|---|---|---|
| **H1：结果依赖目标泄漏或重复场景** | 改动目标可移动尺寸/位置/yaw，保持合法请求不变，unknown-size序列化prompt、ID和顺序必须不变；所有ID引用一致。跨数据源按场景族/等价布局分组去重，train/dev/test及OOF折保存manifest和交集检查；检查全部SFT/偏好/先验阶段 | 输入合同失败则不得主训练。已知问题是真实缺陷；未查清upstream暴露是证据缺口，不能武断写“已泄漏” |
| **H2：两臂名不同而算法/信息不同点不明，或warmstart伪装同起点** | 保存精确fresh-base hash/revision、每阶段父checkpoint、tokenizer、合法输入列表；给两臂一页差异清单。U-J与U-P的明确差异是因子分解；原始请求信息相同，GT尺寸只在oracle。预算上限、实际tokens/步数/配对量/估计器开销均记录 | 若使用legacy或作者数据transfer，只能作历史/迁移参考。若差异清单为空，取消重复训练；若增加reasoning/人类监督，承认是系统包比较，不能单因果归因 |
| **H3：pipeline估计器泄漏，或噪声尺寸造成错误训练标签，基线被人为削弱** | 估计器拟合ID与fold hash；OOF覆盖每个噪声训练样本；test资产尺寸访问为零。chosen/negative按实际输入尺寸和可控输出验证，记录失败/过滤/修复数。预先冻结是否及如何训练OOF噪声，独立检查human/programmatic标签来源 | 无效标签/泄漏先修协议，不能继续训练靠最终指标“洗白”。不相同的标签与预算需明示，不声称纯算法隔离 |
| **H4：OOR降低来自尺寸收缩、漏物体、失败选择或修复器** | 主几何结果含全请求完成/对象覆盖与联合几何验收；尺寸误差/合理性、约束、支撑/碰撞分列。OOR保持完成条件均值+分母，失败不能记0；raw和repair分报，修复不读GT。known-size oracle尺寸不可被修复器改小 | 只有OOR改善不足以判胜。主要终点、尺寸/覆盖守门阈值在test前冻结；如发生取舍，按预先规则报告或不判总胜，不事后挑指标 |
| **H5：挑选有mesh或成功渲染样本，冒充全源视觉质量** | 所有符合共同合同的source做几何；输出前固定真mesh合格视觉子集manifest、逐源覆盖/排除理由、资产轴序/尺寸与渲染配置。方法生成/渲染失败计入该预定子集，不能事后删掉；box/proxy与真实mesh分开 | 几何可覆盖全源，视觉结论仅覆盖合格子集。缺资产是测量覆盖问题，模型输出无法渲染是系统失败，两者分开。不用5例或proxy图冒充FID/全源UR |

“全source”指所有满足明确合同且数据可用的来源均纳入候选/几何评测，并披露每源适用比例；不是每个原始样本无条件准入，更不是全部放进train后再称source-heldout。跨源重复、无效几何和缺字段需要输出前处理。若另设整source留出，该source须排除所有本轮后训练阶段和先验拟合；不扩大为基础模型全部预训练未见的保证。

## 4. 最省资源的执行顺序与授权边界

1. **现在可做（本次仅完成设计文件）**：父代理冻结unknown-size主张、上表两系统及唯一主终点；ModelQA检查合同变换/信息清单/估计器边界；利用已有manifest设计共同划分、OOF和资产资格表。不需要新模型、GPU或付费评分。
2. **训练前离线门检（后续实施）**：修正ID/顺序并重建版本化数据；group去重；拟合尺寸先验/OOF；验证尺寸改变后的监督有效性、确定性格式适配及评分小案例。可在CPU完成，但这些修改/运行不在本次只读授权内，本文未执行。
3. **小dev管线验证后再训练**：先验证U-P估计尺寸接口和标签有效性，不跑整套三任务。通过后，从同一fresh base分别训练U-J与U-P；保存阶段快照、来源/计数/hash及真实预算。只需这两条主链，不额外训练“unknownsize OptiScene改名版”、K-matched两臂或v2。若预算不足，先U-J完成并仅报告阶段/任务结果，不能用旧warmstart补成公平主对照。
4. **先全源几何，再视觉辅助**：dev选择与合同冻结完成后，对同一固定test各评测一次；几何验收和逐源结果先出。真mesh子集先做确定性装配/渲染验证，再开展已约定的视觉/盲评；是否付费GPT评价是另行授权动作，不是主任务必须立刻启动的工作。统计推断/seed资源配置交Statistician，不能把单seed场景bootstrap当训练稳定性证据。
5. **只有明确主张需要时才增加实验**：K-P GT-size oracle通常无需新训练，可辅助定位尺寸误差；原论文忠实训练、reasoning消融、数据规模因果消融、独立SizePredictor均不是默认必做。现有资料缺官方测试ID/人类监督/完整renderer时，不靠开一个“official”训练job补齐证据。

**验收口径**：可以形成一项边界明确的“未知尺寸多源联合生成 vs train-only尺寸估计+条件摆放”研究比较；是否可发表取决于实际结果、贡献与证据，不能预先认证。原论文数字只作背景，known-size模型仅独立参考。主表结论不跨任务、不跨数据、不跨未知warm-start来源升级。
