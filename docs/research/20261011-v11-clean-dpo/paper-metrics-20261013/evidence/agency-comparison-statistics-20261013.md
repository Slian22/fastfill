# Agency Statistician：unknown-size 主任务的最小公平比较设计

日期：2026-10-13。只做设计评审；未启动训练、评审 API 或新评测。应用 experimental-design 技能。当前对象是 **V1.1 直接 JSON SFT→DPO1→DPO2**，不涉及 v2。此前 `/tmp/agency-formal-eval-protocol-20261013.md` 原样保留，审核前 SHA256 为 `f35b64634cfd79d00e9a378f938197c531705638a4de4bd70f8dbc3a482263b0`。

**最终采纳方案：unknown-size 下比较两条主系统 J 与 P。J 为 V1.1 风格的联合尺寸/布局系统；P 为 train-only SizeEstimator→OptiScene 摆放器。先做同基座、同场景、匹配预算的 SFT 比较；若要提出最终系统主张，再给双方匹配的 DPO 阶段预算。** known-size+GT 尺寸只作信息更充分的 oracle 参考，不进入主胜负表。

**决策记录：** 上一版 Statistician 建议优先 J2−C2，以回答偏好训练是否优于等算力继续SFT。父代理采纳 Research/Reality 的 J/P 两系统主线，因为用户的问题是联合系统与可比 OptiScene 系统的比较，而非DPO数学损失效果。本版据此完成整合；这是对研究目标和必做范围的明确取舍，不将不同建议描述成一致同意。C2仅在另提出偏好优化增益主张时追加，不默认第三条必训链。

## 2. 唯一 primary contract：unknown-size joint

输入统一为房间边界、固定障碍、物体类别/合法属性及用户约束；可移动物体真实尺寸、目标位置/朝向、能查询真实尺寸的资产键，以及由这些目标派生的顺序/编号均不提供。场景内对象 ID 从合法原始请求重新建立，使用独立于目标几何的固定置换规则。固定障碍尺寸若属于请求，各臂均可见。

输出统一解析成 `id,size,pos,yaw,on`（不适用字段用共同约定）；相同对象覆盖、单位、坐标、支撑与失败规则。pipeline 可内部调用多个模块，最终也交付这个结构。主指标用 raw 输出；共享修复器另列 system-after-repair，不把修复收益归模型。评估代码可读取 GT 来测误差，推理/修复代码不得借此补答案。

known-size 若展示，输入明确包含真实可移动尺寸，单独表名“GT-size oracle reference”；它回答提供真实尺寸后能做到什么，不证明在主任务优于 joint。无需为了形式完整再训练一个完整 known-size 实验矩阵。v2 只有在另行确认 checkpoint、输入和训练范围后才可加入。

## 3. 可识别差异先于方法名字

若“OptiScene适配版”和 V1.1 的输入输出、直接JSON监督、基座、SFT/DPO损失、程序偏好、负例规则、阶段及预算均相同，它们是同一臂。不同 repo/命名不是实验处理。主贡献应按证据写为**未知尺寸任务扩展、多源数据与系统评估**；此设计不预设新学习算法。

真正可分辨的因素包括 reasoning 监督、是否使用某阶段、偏好负例相对正例继续训练、独立训练场景规模及两步估尺寸/摆放结构。reasoning 只有真实存在且覆盖同一训练场景时才可建臂；若额外生成推理标签，它增加监督和成本，不能描述为只换提示。reasoning、规模和 warm-start 消融均不列入本轮必做矩阵。

## 4. 最小主矩阵：J/P 两条系统链，先匹配 SFT

两系统使用同一 fresh-base revision、相同外部 unknown-size 请求、相同 train 场景和组划分、统一解码政策及容量约束。J内部联合输出；P内部接收由合法输入估计的尺寸，保留摆放器pos/yaw接口。两者共享通用基座权重，**不共享一个已完成SFT checkpoint**，因为学习的输入/输出接口不同。P的尺寸模块、OOF训练和推理成本计入系统账本。

| 臂 | 从何处开始 | 可识别操作 | 用途 |
|---|---|---|---|
| J0 | 共同fresh-base | 直接 JSON joint SFT | 首轮主系统：联合预测size与布局 |
| P0 | 同一fresh-base；train-only尺寸模块 | 用OOF估计尺寸训练OptiScene摆放SFT，最终合成共同输出 | 首轮主系统：先估size再摆放 |
| J1→J2 | J0 | 新合同下DPO1→几何DPO2 | 需要最终系统主张时继续 |
| P1→P2 | P0；尺寸模块按预定规则冻结 | 可实现的布局偏好DPO1→几何DPO2，与J匹配阶段预算 | 与J最终系统成对继续，不用P0替代 |

**主比较按预先锁定的交付阶段选择：SFT系统比较为J0−P0；最终系统比较为J2−P2。** 打开本轮test前必须确定阶段；若终点是最终系统，SFT差异为辅助结果，不能看哪个阶段在test赢就把哪个升为主结果。SFT合同验证在dev完成，是否开展双方DPO由预定目标、合同有效性和预算决定，不由test名次决定。J2−P0混入后训练阶段/预算差异，不能替代matched final比较。

系统比较有意改变联合/两步结构及其训练接口，因而估计完整系统方案的效果，不能拆成某个损失函数或reasoning模块的纯效果。若P另有reasoning监督，必须记录标签来源、覆盖与成本，不把它隐藏为“相同监督”。不因两个方法名字不同就预设算法创新。

需要DPO时，先重建train-only且符合新输入合同的偏好池，旧泄漏顺序pair不能直接沿用。双方匹配训练场景池、质量检查政策和阶段预算，但不能假装偏好答案逐字相同：J能改变size，P只能在给定估计size下改变布局。P的正负例必须按这些估计尺寸重验，不能使用“只破坏size”的无效负例或把GT尺寸补回输入。记录候选生成、有效pair率、各缺陷类型、长度过滤和最终准入数量；若P不能形成有效偏好合同，停在SFT系统结论，不宣布final已匹配。

在独立dev/smoke上计量每阶段forward/backward及reference计算，冻结双方SFT和DPO阶段FLOPs目标/上限、硬件与计量偏差（建议≤5%）。估计器/OOF、reference缓存、候选生成和后处理成本均计入系统账本；同时报告训练主模型预算与全系统总成本，不能靠漏计外围模块制造等算力。不同接口序列长度不同，相同epoch/steps不是相同compute。报告唯一场景/对数、重复曝光、有效token、steps、GPU小时与FLOPs估计；无法可靠匹配时称预算近似匹配。不能同时声称epochs、token曝光和FLOPs都完全相同。

最小必训是J0/P0两条SFT链；最终系统版本是在这两条链上继续，不默认增加C链。单seed首先支持固定训练实例比较；若要概括方法平均收益，预先安排相同seed集合（例如42/43/44）的配对重复，3次也不保证充分功效。资源只够1次就报告1次，不用房间数量伪装训练重复。

**可选控制C2：** 仅当论文另声称“偏好优化优于等算力继续SFT”时，从J0追加同train pair池chosen-only两段SFT，并与J2匹配额外训练算力。此时J2−C2检验偏好训练包相对正例继续训练，仍不单独识别DPO数学损失。没有C2时，J2−J0只能描述阶段变化，不能排除额外训练量的解释。本报告不把C2列为默认必训。

### 如何处理其余混杂，避免扩大矩阵

| 因素 | 本轮最小处理 | 若将来要声称该因素有益才追加 |
|---|---|---|
| 系统/训练接口 | J/P有意改变联合预测与估尺寸后摆放结构；同阶段比较 | 若要拆解reasoning或DPO作用，再有针对性追加控制 |
| 数据规模/来源组成 | 主比较固定同一个多源训练池与来源采样规则 | 相同方法、同预算、同来源比例的嵌套小/大训练池；记录独立group数 |
| warm-start | 全部主臂同fresh-base；legacy不参与主效应估计 | 有可审计暴露历史的另一个起点；上游不明权重不能声称干净因果对照 |
| 额外compute | J/P匹配SFT阶段；final主张再匹配双方DPO阶段及系统成本 | 偏好相对继续SFT增益才追加C2；预算曲线不依据test补挑 |

固定因素可以消除该比较中的混杂，却不等于测出了该因素的效应。当前无需一次做满方法×数据×起点×算力因子实验。

## 5. 主系统P：SizeEstimator + OptiScene pipeline

**推荐，结构差异比把 OptiScene 增加 size 输出更清楚；它是同初始信息下的两步系统基线，不是原论文复现。** 第一模块从合法类别/房型/上下文估 size；known-size摆放器接收估计尺寸，仅输出原有pos/yaw等布局字段；最终把估计size和布局合成共同输出。绝不能用test资产目录、GT bbox或可回查尺寸的资产ID获得size。

最省成本第一模块采用 train-only 的 `category×room_type` 分维中位数；桶内少于20个不同group时退回category，再不足退回全train中位数。桶计数、轴序、回退与任何裁剪界限都只由train定义。20是预设稳定性规则，不是统计保证。独立 SizePredictor 可后续替换，不成为当前必做。

**OOF要求：** train按house/group连通分量分5折；为每折产生尺寸时，先验/预测器完全只用其他4折，回退和归一化也一样。摆放器训练输入使用这些 OOF 估计尺寸，监督目标位置/朝向来自该训练场景。dev/test尺寸由全部train拟合的最终估计器产生。若可用group少于5，按实际group数降低折数；不足2组不能生成诚实OOF，该来源只用其他训练来源可用先验并披露。不要让摆放器只用GT尺寸训练、测试突然换估计尺寸而把分布失配当算法结论。

注意：GT位置相对于有误的估计尺寸可能不再无碰撞。这是两步任务的训练噪声，需统计披露；不得利用该场景真实尺寸偷偷修正输入。若要调整训练布局，必须另声明统一、只使用估计尺寸的规则和新增成本，不能隐式进行。

| 外部臂身份 | 实际能回答的问题 | 不能声称 |
|---|---|---|
| **Matched pipeline P0**：同fresh-base、同train场景，在OOF估计尺寸上训练摆放SFT，成本包括尺寸模块 | 与 **J0** 同阶段比较两步结构和joint结构；共同数据/初始信息 | 原论文复现；纯DPO效果 |
| 原作者数据/已有权重训练的placement + train-only估计器 | 现成摆放器迁移到本任务的 transfer reference | 排除训练数据、warm-start、compute混杂 |
| 原模型 + GT尺寸 | 信息更充分的oracle参考 | unknown-size公平胜负 |

P0与J0是本方案的两条主系统；原作者训练权重的transfer版本不能替代P0。若交付范围停在SFT，就只提出SFT系统结论；若要提出最终系统结论，必须按第4节同时建设J2/P2。不能把J2对P0的优势全归因联合架构，也不因为P的DPO需要适配就自动免除该阶段对照。

## 6. 多源划分：group为分割单位，来源为报告单位

先建立硬盘全部来源的 `source,raw_id,house/building,group,aliases,room_type,asset_eligible,canonical_scene_id` 清单。跨来源的相同房屋、别名和已识别重复场景组成连通分量，全分量进入同一split；物体/房间行不能各自随机切分。原始重复视图不当独立房间，新的canonical去重规则在看分数前固定。保留所有来源清单及缺失原因，几何合法性/输入可用性规则各臂一致。

来源内 ID 目标比例 train/dev/test=80/10/10，使用固定seed的连通分量分配，平衡各来源房间数并记录实际偏差，不为凑比例拆house。至少3个可分组件的来源尽量各保留≥1 dev和test；仅2组可1 train/1 test，无独立dev；仅1组放rare-source test-only诊断，不在训练同时使用。跨来源组件约束优先于配额。

**source-heldout：** 在看新模型结果前选定2个来源，全部排除出train和调参dev；如果沿用SceneSmith/SpatialGen，说明只保证本次fine-tuning未见，不能证明通用基座预训练未见。连到heldout来源的跨源alias分量也排除训练。其他来源保留ID test；ID与source-heldout分开汇总，heldout不能反过来充当dev。若用户要求每个来源都进入训练，则不能同时声称单个模型有完整source-heldout来源；这两个目标需要明确取舍，本方案选择“所有来源进入评估清单”，其中2个留作OOD。

## 7. 可直接执行的抽样与统计表

主比较只包含J/P两系统：本轮阶段在test前锁定为J0/P0或J2/P2。所有配对评估使用相同请求、seed、统一解码政策和匹配预算；估计尺寸是P的train-only中间变量，不能获得额外GT输入。C2只有单独主张需要时才追加，不进入默认采样/调用预算。

| 层级/指标 | 抽样规则 | 固定分母/失败策略 | 汇总与不确定性 |
|---|---|---|---|
| 多源几何、解析完整率、raw联合验收 | 所有新ID test及heldout test合法请求，全量 | 全请求N；生成失败验收=0。raw与repair分开；资产缺失不剔除几何 | 主终点：ID来源等权macro raw验收差J−P，阶段预先锁定；每来源先房间均值，再等权。配对重采样完整house/group连通分量 |
| OOR、尺寸误差/尺寸IoU | 同上全量 | OOR失败为缺测且报failure，不填0；尺寸IoU另报失败=0及共同完成子集 | 来源分层与raw/repaired；尺寸IoU仅维度，不是完整布局IoU。防止把缩小尺寸带来的低OOR当整体质量提升 |
| 真实资产FID | 全test资产资格场景尝试渲染；每场景固定一个视角 | GT及两比较臂共同成功ID；列原N、资格数、各臂成功和共同n。失败不黑图填充、不补样 | 每来源/任务分别FID；pool需合并图重算，不能平均FID。小n仅描述，无显著胜负；n<2不计算 |
| 配对GPT三维 | 每来源q_s=min(20,N_s)，从完整test预抽，相同ID给两臂；见下方房型配额 | selected q_s不变，缺资产/渲染/API失败不补；均值条件于有效评分，配对差条件于两臂均有效 | 分别functionality/layout/aesthetics；来源/房型权重明确，cluster CI探索性；不是人工UR |
| 真实UR，可选独立人工量测 | 从每来源GPT固定清单嵌套取min(5,q_s)，不按分数/可视效果选择；两臂同ID | 每个有效布局5名真人，≥3认可为usable；保存逐票。模型无输出计系统失败；资产/API等评估设施缺失另列不可评，不自动作模型失败 | 场景为单位、5票不等于5个独立场景；配对差按house/group处理；小样本不下方法胜负结论 |

GPT房型配额：冻结 bedroom/living/kitchen/bathroom/other 五个抽样桶映射，保留原始房型标签，other仅用于配额且不改论文六层定义。每非空桶先分1名额，余量按剩余房间数比例用最大余数法分配，桶内按固定salt/seed42及canonical ID的hash取最前，禁止换seed。若q_s小于桶数，则按房间数比例配额，不要求每桶必有样本。公布每桶N_sh/n_sh与入选概率。18来源且样本充足时为≤360请求×2臂=≤720次初始GPT调用；UR≤90场景×2臂×5人=≤900次真人判断，不是已授权启动。

**权重：** 全量几何 pooled=`sum_s N_s*mean_s / sum_s N_s`回答当前房间混合；source-macro=`mean_s mean_s`回答当前列出来源的平均表现；两者都报，主终点预定macro以避免大来源支配。source-heldout另表，rare-source单列。GPT有完整观测时先用N_sh/N_s还原来源均值，再计算source-macro或pooled；等额抽样直接平均不是room-pooled。缺失时标条件性、公布覆盖，不能靠加权消除非随机失败。资产资格与可渲染失败会选出较容易/资产完善的子集；视觉表现不可外推全部几何队列。

**推断：** 当前每个固定模型的几何主差用2,000次配对cluster bootstrap/seed42，重采样单位为全局house/alias连通分量；每次重新计算预先固定的来源权重，跨来源同组件同步抽样。报告每来源group数；来源只有1组不能制造来源内抽样方差，单列其有限样本描述，不把退化CI当确定。只有一个预设主终点使用95%区间；OOR/FID/GPT/UR/子组均为次要或探索性，不据其中最好的结果宣布胜者。多训练seed时同时列每seed差值和跨seed离散；不能只合并房间后忽略训练随机性。没有预定有意义差值/非劣界限就不作等效、非劣或功效充分声明。FID有限样本偏差也不会因为两臂n相同就消失：[Chong & Forsyth, CVPR 2020](https://arxiv.org/abs/1911.07023)。

实现补充：在冻结test manifest时把test独立组件少于2个的来源归入rare-source描述表，仍计算几何和全来源macro点值，但不让它们产生貌似精确的总体CI；主推断macro明确限定为其余ID来源，并单独标注来源名单。若各来源组件互不相交，可按来源内整组件重采样，来源权重保持固定；若存在跨来源组件，采用全局共享组件权重的配对cluster加权bootstrap（每次每组件抽一个Exp(1)权重，同组件所有行和两臂共用，来源内重新归一化），避免拆开依赖或抽出空来源。上述2,000次与seed42不变，跨源时所用的是加权bootstrap，不能称普通有放回抽样。来源/group数量少时区间仍仅探索性。

主终点是盒级检查代理；尺寸误差与约束满足是关键副结果。即使macro验收改善，尺寸或约束退化时也须报告取舍，不以单指标称所有质量改善。未来若要正式人类质量主张，需要另预设UR最小有意义差值并按配对不一致率/group相关做功效规划；不能把这里的5/20配额当作已经有80%功效。

## 8. 省算力执行顺序与停止边界

1. **先冻结合同和split，不训练。** 从每来源train/dev抽独立smoke，验证输入无GT派生信息、ID稳定、尺寸轴序、target解析、固定障碍和多源缺资产账本。test不用于选相机/提示/阈值。
2. **小规模matched SFT pilot。** 两系统共享来源均衡、group约束的至多2,000个train场景，P先生成train-only先验及OOF输入，分别训练J/P pilot。每来源dev至多20场景只做合同/流程诊断，不看test。检查token预算、输出完整性、尺寸量纲、P输入噪声及数据路径；不能要求pilot胜过legacy才继续，也不能因test落后换方案。
3. **合同通过再完成选定阶段。** 先J0/P0；若预定交付final system，双方继续J1→J2/P1→P2并匹配阶段预算。checkpoint选择规则提前固定，推荐固定预算末checkpoint，不做test选winner。pilot数据/超参改动写版本；新配方在dev确定后执行冻结test比较。SFT-only与final目标必须在打开本轮test前选定。
4. **几何先全量，视觉分层后运行。** 视觉使用上述预抽IDs和资产全量coverage，不因为几何分数选择好看的来源/场景。旧formal-eval的300/六层抽样继续作为legacy，不能替代新多源共同清单。
5. **不默认增加第三链。** C2、reasoning、规模及warm-start消融仅在明确新增相应主张时追加。现有作者数据模型只以transfer reference记录，不能用它代替P主系统；GT-size oracle与legacy诊断保持独立。

推荐最终表述：“我们在共同fresh-base、训练场景、初始信息和匹配预算下，比较未知尺寸的联合尺寸/布局系统J与train-only估尺寸→OptiScene摆放系统P。先验证matched SFT；最终系统主张要求双方同阶段DPO预算。现有warm-start、作者数据迁移模型与GT尺寸oracle分别保留为参考。该比较不单独识别DPO数学损失效果，也不预设新算法；只有另声称偏好优化优于等算力SFT时才追加C2。”
