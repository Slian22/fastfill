# Audit addendum — 2026-10-11

This addendum records source and data-integrity findings from the fresh full V1.1 audit. It is not a change to the frozen hypothesis, scoring code, decoding, model recipe or cohort rows, and it does not depend on comparing new model quality outcomes.

The original corpus preserves the V1 object ordering and category-index assignments derived from reference footprint sizes and pose tie-breaking. Every one of 144,150 training, 8,167 validation and 8,647 test input rows was checked. V1.1 removes explicit object size/position/yaw/support fields from prompts, but preserves that ordering. The current experiment therefore supports a diagnostic stage comparison conditional on this input contract. It does not establish size-unknown deployment validity for arbitrary unordered inventories. A new target-independent protocol requires new data identities and training, not a mid-run evaluator reorder.

The machine-readable interpretation is in `interpretation-addendum.json` and binds all four original cohort hashes. The new final report gate adds independent CPU rescoring using the original evaluator and its original Python interpreter, validates DPO training and merge provenance, and labels the research scope diagnostic only. Existing frozen code and completed SFT generations are retained.

The audit reproduced additional engineering failures: unsafe checkpoint replacement and silent restart on partial checkpoints; missing clean-model lineage enforcement and symlink output isolation; unprotected scored-chunk payload; unsafe legacy pair-cache reuse and labels; partial dataset rebuild mixing old files; and RoomGenBench cyclic fallback/asset provenance errors. Local fixes are tested separately. The server deployment receipt will distinguish the active frozen experiment from the hardened helper version, and will record any replaced pending jobs. The original GPU allocation cap remains 84 GPU-hours; audit-only CPU allocations request zero GPUs.
